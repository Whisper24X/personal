# Testcase Author

## 适用时机

- 用户要新建自动化用例。
- 用户要把旧用例改成更适配 Agent 的写法。
- 用户反馈"用例描述不清、执行分歧大、误判多"。

## 依赖文件

- `references/case-template-v2-lite.md`

## 编写步骤

1. 先写 `任务目标`（1句话）与 `完成断言`（最多 2-3 条）。
2. 再写样本策略（优先样本 + 备用样本 + 偏离口径）。
3. 补 Stage0 预检（数据/权限/入口/能力位）。
4. 填解阻预算：
   - 最大循环数 N（默认 2，L2 建议 3）；
   - 单卡点 round1/2/3 的单变量梯度。
5. 填最小证据集与回滚要求（有写操作时）。
6. 用失败归因口径复核是否可落 `PASS/FAIL/BLOCKED_*`。

## 编写检查清单

- [ ] 断言可被观测（UI/接口/回读至少其二）
- [ ] 样本偏离不会改变目标
- [ ] 解阻变量是"单变量"且可执行
- [ ] 失败时有最小证据，不会"无证据阻塞"

## 输出模板

当用户要求"给我一条可执行 case"时，使用以下结构：

```markdown
### A. 用例元信息
### B. 目标与断言
### C. 样本与入口
### D. Stage0预检
### E. 解阻预算
### F. 自愈边界
### G. 证据要求
### H. 结论归因
### I. 回滚要求（如适用）
### J. 执行记录字段
```
