# 5.18 工作流整理

## 1. `ROM` 回归与问题同步工作流

适用于版本回归、专项验证、与工厂同步问题。

1. 明确本次回归范围与版本内容。
2. 执行 `ROM` 回归测试。
3. 记录测试过程中发现的问题与现象。
4. 对问题做初步分类，整理成 `buglist`。
5. 将 `ROM bug` 和 `buglist` 同步给工厂。
6. 跟进处理结果，必要时补充复现信息。
7. 修复或版本更新后，进行简单回归验证，确认问题是否关闭。

可概括为：

`ROM` 回归测试 -> 问题记录 -> `buglist` 整理 -> 同步工厂 -> 修复后回归验证

## 2. `bug` 跟踪、复现与复测推进工作流

适用于“葱搭 `bug`”这类需要跨角色协同推进的问题。

1. 接收并确认 `bug` 信息来源。
2. 与业务、产品或测试确认问题现象和触发条件。
3. 尝试复现问题，补充复现步骤与环境信息。
4. 将复现结果同步给相关角色。
5. 跟踪问题处理进度，推动进入复测阶段。
6. 复测后确认结果，并继续做相关回归。
7. 完成闭环记录，避免问题丢失或重复跟进。

可概括为：

问题收集 -> 复现确认 -> 同步相关方 -> 推动复测 -> 回归验证 -> 闭环

## 3. 工单处理工作流

适用于日常查询工单、客服咨询、线上问题响应。

1. 查询待处理工单或客服咨询。
2. 判断问题类型与优先级。
3. 能直接解答的先快速处理。
4. 需要复现或排查的，补充信息并进入问题跟踪。
5. 如涉及版本或功能异常，转入 `bug` 流程处理。
6. 处理完成后反馈结果，并确认是否还需后续动作。

可概括为：

工单查询 -> 分类判断 -> 直接解答 / 进入排查 -> 同步结果 -> 关闭

## 4. 回归 `case` 整理与专项验证工作流

适用于研学支付、功能基础回归等专项测试准备。

1. 明确专项场景，例如研学支付、重点功能模块。
2. 梳理已有问题与历史高频风险点。
3. 整理对应回归 `case`。
4. 按 `case` 执行验证。
5. 输出异常项并同步相关角色。
6. 问题修复后再次复测，更新 `case` 经验。

可概括为：

专项场景确认 -> 回归 `case` 整理 -> 执行验证 -> 输出问题 -> 复测更新
