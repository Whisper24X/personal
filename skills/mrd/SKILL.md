# 生成 MRD

将产品想法或需求描述转化为结构化的市场需求文档（MRD）。

## 输出规范（强制）

> **重要**：以下规范必须严格遵守，不可违反。

| 项目           | 规范                                                                       |
| -------------- | -------------------------------------------------------------------------- |
| **输出文件名** | `MRD.md`（必须使用此文件名，不可使用其他名称如"市场需求文档.md"）          |
| **文件数量**   | 只生成 1 个文件，禁止创建额外的说明文件或拆分文件                          |
| **文档结构**   | 必须严格按照 [mrd-template.md](references/mrd-template.md) 的 7 个章节结构 |

## 核心原则

1. **聚焦 Why 和 What**：MRD 关注问题定义、用户价值、业务目标，不涉及具体实现
2. **可量化**：成功标准必须有基线和目标值
3. **边界清晰**：明确做什么、不做什么
4. **边界交叉识别**：如果当前需求和用户提出的需求有边界上的交叉，必须明确描述出来
5. **状态和边界变化描述**：如果有状态或边界上的变化，必须详细描述变化后的规则和状态
6. **风险前置**：识别不确定点和风险

## 生成流程

### Step 1: 读取模板

首先读取 [mrd-template.md](references/mrd-template.md) 获取完整结构。

### Step 2: 收集信息

从用户输入中提取：

- 要解决的核心问题
- 目标用户是谁
- 典型使用场景
- 期望达成的目标
- 已知的约束条件
- **边界交叉情况**：当前需求与用户提出需求之间的边界交叉点（如有）
- **状态和边界变化**：识别是否存在状态或边界上的变化，如有则收集变化前后的对比信息

### Step 3: 按模板生成 MRD

依据模板的 7 个章节填充内容：

| 章节              | 核心要点                                                                                     |
| ----------------- | -------------------------------------------------------------------------------------------- |
| 1. 背景与问题定义 | 核心痛点、不解决的后果                                                                       |
| 2. 目标用户和场景 | 用户画像、2-3 个典型场景                                                                     |
| 3. 目标与成功标准 | 业务目标、可量化指标                                                                         |
| 4. 核心需求范围   | P0/P1 功能、明确不做的范围、**边界交叉情况**（如有）、**状态和边界变化**（如有，需详细描述） |
| 5. 关键约束       | 时间、技术、成本、合规约束                                                                   |
| 6. 不确定点和风险 | 待确认问题、已识别风险                                                                       |
| 7. 备注           | 竞品参考、技术参考、工程评估信息                                                             |

### Step 4: 检查清单

- [ ] 核心问题定义清晰（2-3 个要点）
- [ ] 至少 2 个典型场景
- [ ] 成功标准有基线和目标值
- [ ] P0/P1 功能区分明确
- [ ] 明确列出不做的范围
- [ ] **边界交叉情况已识别和描述**（如有）
- [ ] **状态和边界变化已详细描述**（如有，包括变化前后的规则和状态对比）
- [ ] 风险和不确定点已识别

## 信息不足时的处理

| 缺失信息         | 处理方式                                          |
| ---------------- | ------------------------------------------------- |
| 用户规模不明     | 标注「待确认」，放入第 6 章                       |
| 成功指标无基线   | 建议指标类型，标注需补充基线数据                  |
| 约束不清晰       | 放入「待确认约束」                                |
| 竞品信息缺失     | 可省略或标注「待补充」                            |
| 状态变化规则不明 | 标注「待确认」，放入第 6 章，并说明需要补充的信息 |
| 边界变化细节不足 | 标注「待确认」，放入第 6 章，并说明需要补充的信息 |

## 状态和边界变化描述要求

当识别到状态或边界上的变化时，必须在第 4 章「核心需求范围」中详细描述：

1. **变化前状态**：描述变化前的规则、边界定义、状态机制
2. **变化后状态**：描述变化后的规则、边界定义、状态机制
3. **变化原因**：说明为什么需要这个变化
4. **影响范围**：说明这个变化会影响哪些功能、用户或业务流程
5. **迁移考虑**：如有需要，说明从旧状态迁移到新状态的注意事项（可选）

## 禁止事项

以下行为是禁止的，违反将导致输出无效：

1. ❌ 使用非 `MRD.md` 的文件名（如"市场需求文档.md"、"需求文档.md"等）
2. ❌ 创建多个文件（如一个说明文件+一个 MRD 文件）
3. ❌ 省略模板中的任何章节（即使信息不足也要标注"待确认"）
4. ❌ 输出不完整的占位符内容
