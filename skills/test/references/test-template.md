## 第二部分：测试用例

### 用例编写规范

#### 优先级定义

| 优先级 | 定义     | 说明                       |
| ------ | -------- | -------------------------- |
| P0     | 核心功能 | 主流程、核心业务，必须通过 |
| P1     | 重要功能 | 重要分支、常用功能         |
| P2     | 一般功能 | 边界条件、异常处理         |
| P3     | 低优先级 | 极端场景、优化建议         |

#### 用例格式说明

- 采用 **Given-When-Then** 格式（BDD风格）
- **Given**：前置条件和测试数据准备
- **When**：执行的操作步骤
- **Then**：预期结果验证

## 附录：测试用例生成指南

### 强制要求

1. **用例覆盖完整性**：
   - 必须覆盖PRD中所有功能点
   - 必须包含正向场景和异常场景
   - 必须包含边界条件测试

2. **用例格式规范**：
   - 统一使用 Given-When-Then 格式
   - 每个用例必须有唯一ID
   - 每个用例必须标注优先级
   - 每个用例必须标注类型（适用端）

3. **测试数据要求**：
   - 测试数据必须具体、可执行
   - 不允许使用模糊描述如"某用户"
   - 必须包含边界值数据

4. **预期结果要求**：
   - 预期结果必须可验证
   - 包含返回值、状态变化、副作用验证
   - 异常场景必须验证错误信息

5. **用例数量要求**：
   - 每个功能模块至少3个测试用例
   - 包含：正向场景、边界条件、异常场景

### 输出格式要求

- 使用 Markdown 格式
- 严格按照测试文档模板结构
- 用例描述清晰、步骤可执行
