# 公众号文章生成

帮助作者把素材整理成适合发布在自己公众号、博客或个人内容平台上的文章。

## 作者自定义优先

这是作者自己的写作技能，不绑定第三方品牌或第三方平台模板。

若项目内存在作者自定义模板、固定结尾、参考文章或排版规范，一律视为作者自己的长期配置，默认优先遵循。

优先级如下：

1. 用户在当前对话里的明确要求
2. 当前技能目录下的参考资料
3. 本技能中的长期固定偏好
4. 通用写作常识

以下内容若未明确提供，不要擅自补全：

- 公众号名称
- 固定结尾
- 产品推广段落
- 品牌口号
- 平台专属格式
- 作者职业身份标签

项目内已有的配置，一律视为作者自己的配置。

## 工作流

严格按 9 个步骤顺序执行，不跳步，不合并。

### Step 1，理解作者意图

用 `AskQuestion` 或直接提问，确认：

- 切入角度
- 深度偏好
- 核心主旨
- 真实素材与禁写细节

推荐长文为 4000 到 8000 字，但结构完整优先。素材不足时可以写短，不得编造细节、数据或场景。

### Step 2，阅读参考资料

优先读取：

1. `references/范文风格分析.md`
2. `references/行文风格指南.md`
3. `references/公众号排版模板.md`

如果这些文件存在，应在写作前先读取，用来校准语感、格式和禁令。

### Step 3，设计大纲

大纲至少包含：

- 开头场景
- 章节论点
- 叙事功能
- 结尾收束方式

把大纲给作者确认后，再进入下一步。

### Step 4，编写初稿

根据确认后的大纲写初稿。若用户未给输出路径，先确认保存目录。

### Step 5，独立审读

调用 `subagent` 审读初稿，重点检查：

- AI 味
- 逻辑连贯性
- 结构是否过于工整
- 信息密度和叙事节奏

### Step 6，事实核查

调用 `subagent` 核查事实性内容：

- 数据和数字是否有来源
- 事件和场景是否来自真实素材
- 产品名、术语拼写是否准确
- 引用是否有出处

无法追溯的内容必须标记为「待作者确认」或删除。

### Step 7，修改初稿

根据审读和核查反馈修改：

- 删除或改写不实内容
- 修复 AI 味
- 增加个人视角、情绪和具体细节

### Step 8，终审自检

调用 `subagent` 按本文自检清单独立终审。

### Step 9，完成终稿

完成最终修改后，至少产出以下 3 份文件：

1. `标题.md`
   - 完整工作稿
   - 文末保留自检报告
2. `标题-公众号发布版.md`
   - 面向发布
   - 不包含自检报告
   - 不包含排版提示
3. `标题-公众号排版版.md`
   - 严格遵循 `references/公众号排版模板.md`
   - 包含题图、插图、建议加粗等排版提示
   - 用于复制到公众号编辑器后二次机械排版

若用户只要求其中一种产物，再按用户要求缩减。

完成后，更新文件，并给出 3 个标题推荐。

## 默认写法

若作者未提供额外说明，默认遵循以下方向：

- 毒舌但真诚
- 数据与故事双驱动
- 冷静平和，但有力量
- 不端着，不说教，像有见识的朋友在认真聊天

语感细节优先以 `references/范文风格分析.md` 为准。

## 可选写法

根据素材自然选择，宁可不用，也不要生硬套用。

- **回环呼应**，前文细节在后文回扣
- **层层剥开**，现象到追问再到洞察
- **叙事弧线**，问题、行动、结果、收束

## 内容要求

- 先有真实场景，再有观点
- 段落长短交错，避免连续长段
- 加粗克制，只强调关键判断
- 技术细节够用即可，不贴大段代码
- 复杂内容尽量生活化解释

## 高频禁令

具体规则以 `references/行文风格指南.md` 为准。主文件只保留高频禁令：

- 不写空话开头，必须从具体场景切入
- 不用套话，如「首先」「综上所述」「值得注意的是」
- 不用空泛工具名，优先写真实产品名；若作者不想暴露，则沿用作者允许的抽象指代
- 不用 Markdown 表格，除非非常小且必要
- 不使用冒号、破折号、双引号，引用统一用「」

## 固定结尾

作者提供了固定结尾，就原样保留。

作者未提供固定结尾，就不要自动添加推广段落、公众号引导或产品广告。

## 题图与插图

- 提供题图和插图 prompt
- prompt 应可独立使用，不依赖上下文
- 题图放文首，比例 `4:3`
- 插图用于帮助理解复杂逻辑或概念
- 图中文字全部使用中文，风格保持统一

## 文档格式

保存到作者自己的内容目录。若路径不明，先确认。

若存在 `references/公众号排版模板.md`，则在用户未明确指定其他格式时，必须按该模板生成 `公众号发布版` 与 `公众号排版版`。

### 默认文件分层

- `标题.md`
  - 作为完整工作稿
  - 可以保留自检报告、配图 prompt、写作备注
- `标题-公众号发布版.md`
  - 仅保留标题、正文、固定结尾
  - 不保留排版提示、自检报告、过程备注
- `标题-公众号排版版.md`
  - 用于公众号编辑器粘贴前处理
  - 保留 `［题图建议放这里］`
  - 保留 `［插图建议放这里］`
  - 保留 `［建议加粗］`
  - 章节标题默认使用 `一，二，三` 的形式

### 排版版硬性规则

- 标题单独一行
- 标题后空一行，再放 `［题图建议放这里］`
- 正文段落之间保留空行
- `［建议加粗］` 最多出现 3 次，只用于关键判断句
- `［插图建议放这里］` 只在确实有助于理解时出现，默认 0 到 2 处
- 不在排版版中使用 Markdown 标题语法、列表语法或表格语法
- 不把提示语写成解释句，例如不要写「这里建议加粗一下」，必须使用固定标记
- 公众号发布版必须删除全部排版标记后再保存

若作者需要 `front matter`，使用以下格式：

```yaml
---
id:
created: YYYY-MM-DD
weekId: YYYY-ww
published:
status: draft
tags:
  - projects/公众号文章
---
```

## 自检清单

Step 8 由 `subagent` 独立执行，至少检查：

- 字数和结构是否合理
- 是否违反标点和套话禁令
- 是否使用空泛工具名
- 是否有编造内容
- 加粗和段落节奏是否克制
- 观点是否具体，有无回环
- HKR 评分
- 活人感是否通过

### 自检输出格式

把自检结果附在文末，不计入正文字数：

```text
---自检报告---

📏 硬性规则：✅ 全部通过 / ❌ 未通过项：[列出]
🎨 风格一致性：✅ 全部通过 / ⚠️ 需注意项：[列出]
📊 HKR 评分：H ★★★☆☆ / K ★★★★☆ / R ★★★☆☆
   - H：[一句话说明趣味性/悬念感]
   - K：[一句话说明信息增量]
   - R：[一句话说明情绪共鸣点]
👤 活人感终审：✅ 通过 / ❌ 未通过
   - [一句话总评，说明读感是「朋友在聊天」还是「AI 在输出」]
📝 字数统计：[正文字数]
🖼️ 配图清单：题图 ×1 / 插图 ×[N]

修改建议（如有）：
1. ...
2. ...
```
