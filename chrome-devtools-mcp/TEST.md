### 2. 项目概述

#### 2.1 项目背景

本期建立覆盖小程序与抖音等渠道的**统一研学履约闭环**：商品/订单模型、支付拆单、抖音券与父订单映射、预约与取消、出行完成、退款分摊与同步、电子合同签署、开课短信提醒。目标为状态可解释、账务可对、合规触点（合同/短信）可观测，并支撑 PRD 第 3.2 节 KPI 埋点回收。

#### 2.2 测试目标

- 验证系统功能符合 `docs/PRD.md` 第 8 章 P0 功能规格与第 14 章验收范围
- 验证关键体验约束（第 4.3 节 MUST，如关键操作 ≤3 秒反馈）可落地
- 发现并记录缺陷，评估发布与灰度风险（对齐第 13 章）

### 模块：商品与订单模型

#### TC-001：预约类支付成功后子订单数量与次数一致 - 正向

| 属性     | 值                                      |
| -------- | --------------------------------------- |
| 用例ID   | TC-ORD-001                              |
| 优先级   | P0                                      |
| 前置条件 | 已配置预约类商品，总预约次数为 N（如 3） |
| 关联需求 | PRD-8.2 商品与订单 AC1                  |

**Given**：

- 商品类型为预约类，后台配置总次数为 3
- 用户 `u_parent_01` 已登录小程序

**When**：

- 用户完成该商品支付且系统确认支付成功
- 用户进入订单详情查看子订单列表

**Then**：

- 子订单数量为 3，与商品配置一致
- 埋点或后台可查到 `sub_order_generated` 与父订单关联正确

**自动化就绪**：

- **可行性**：🟡 小程序下单 + 🟢 后台列表交叉校验子订单数量。
- **Given（浏览器/MCP）**：`SHADOW_BASE` 已部署可访问；账号具备 `sub_order_view`；小程序侧测试号已登录（开发者工具或真机）。
- **When（小程序）**：完成支付并进入订单详情；**等待**支付确认接口成功且详情骨架消失。
- **Then（小程序可观测）**：详情中子订单条目数 = 3（或等价区块展示一致）。
- **When（管理后台，可选）**：浏览器打开 `{SHADOW_BASE}/order/subOrder`（或侧栏 **订单管理 → 子订单管理**）；在「渠道订单编号」搜索框（`placeholder="请输入渠道订单编号"`）输入父单关联编号并查询；**等待**表格加载完成。
- **Then（后台可观测）**：与测试父单关联的子订单行数 = 3；「服务状态」等列有值且可导出（若测导出则点击「导出订单」后出现下载或成功提示）。
- **元素提示**：`ainative-shadow/src/pages/orderManagement/subOrder/index.vue` — 表头含「渠道订单编号」「服务状态」「订单状态」。

- **Then**：同一订单在渠道单页与子单页的服务/订单状态文案与小程序订单详情同一语义（可截屏对比或文本包含关系断言）。
