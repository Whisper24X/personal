## 🎓 知识点总结

### 为什么小程序不需要构建？

1. **Taro 自动处理**: Taro CLI 在执行 CI 命令时会自动编译代码
2. **一体化流程**: 编译 + 上传一步完成
3. **无需服务器**: 验证方式是扫码，不是访问 URL

### 工作原理

```
make app-preview
    ↓
cd ainative-app && pnpm ci:weapp:preview
    ↓
taro build --type weapp --preview
    ↓
读取 config/index.ts 配置
    ↓
根据 mode 加载 ci.test.config.js 或 ci.config.js
    ↓
调用 @tarojs/plugin-mini-ci 插件
    ↓
使用 miniprogram-ci SDK 上传代码
    ↓
微信 CI 服务器生成二维码
    ↓
二维码保存到本地 / 返回 URL
    ↓
开发者扫码预览
```

## 🆚 对比分析

### 与传统 Web 项目对比

| 特性 | Web 项目 | 小程序项目 |
|------|---------|----------|
| 构建命令 | `npm run build` | 无需（Taro 自动处理） |
| 构建产物 | `dist/` 目录 | 临时文件（自动清理） |
| 部署方式 | 上传到服务器 | 上传到微信 CI |
| 配置复杂度 | 需配置 nginx、域名等 | 只需配置私钥 |
| 验证方式 | 访问 URL | 扫描二维码 |
| 验证时间 | 5-10 分钟 | 1-2 分钟 |
| 需要服务器 | ✓ | ✗ |
| 需要域名 | ✓ | ✗ |

### 与手动上传对比

| 操作 | 手动上传 | Make 命令 |
|------|---------|----------|
| 打开开发者工具 | 必须 | 可选 |
| 选择项目 | 必须 | 自动 |
| 点击上传 | 必须 | 自动 |
| 填写版本号 | 必须 | 自动（配置文件） |
| 填写描述 | 必须 | 自动（配置文件） |
