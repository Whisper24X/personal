# 对话知识沉淀 — 插件使用说明

本文面向运维与二次开发，说明如何开启/关闭、更换实现、扩展自定义插件与排障。架构与数据契约的权威来源仍为 [知识沉淀-方案.md](./知识沉淀-方案.md) 与 [知识沉淀-详细设计.md](./知识沉淀-详细设计.md)；本文聚焦操作与扩展，避免重复规范条文。

## 1. 能力总览

| 能力 | 时机 | 说明 |
|------|------|------|
| **ingest（沉淀）** | 任务进入 `done` 后异步入队 | 从各节点 `output.jsonl`、任务日志等汇聚内容，经候选池与 LLM 写入 `docs/memory/**`；**不阻塞**主状态机，失败**不**回滚任务 `done`。 |
| **inject（注入）** | 每次 Runner 节点执行前 `prepareExecution` | 在 `resolvePrompt` 之后将记忆块追加到最终 prompt；关闭时为空。 |

## 2. 环境变量（常用）

| 变量 | 含义 | 默认（开发） |
|------|------|----------------|
| `MEMORY_EXTRACTION_ENABLED` | 是否启用沉淀入队与消费 | `false`（联调前建议关） |
| `MEMORY_INJECTION_ENABLED` | 是否在执行前注入记忆块 | `false` |
| `MEMORY_INGEST_PLUGIN_ID` | 沉淀插件 id | `ainative.default` |
| `MEMORY_INJECT_PLUGIN_ID` | 注入插件 id | `ainative.default` |
| `MEMORY_LLM_BASE_URL` | 可选；OpenAI 兼容 API 根（如 `https://api.openai.com/v1`） | 不配则见下方「默认 LLM 解析优先级」 |
| `MEMORY_LLM_API_KEY` | 可选；Bearer Token | 不配则同上 |
| `MEMORY_LLM_MODEL` | 可选；模型名 | 不配则由 DB / `OPENAI_MODEL` / 默认 `gpt-4o-mini` 决定 |
| `MEMORY_CONFIDENCE_MIN` | 事实最低置信度 | `0.65` |
| `MEMORY_PROMOTION_SCORE_MIN` | 写库前门限（与冷启动路径并存） | `0.75` |
| `MEMORY_PROMOTION_COLD_START` | 无召回统计时是否用 `confidence` 退化门限 | `true` |
| `MEMORY_PREPROCESS_CANDIDATE_BUDGET_CHARS` | 候选池总字符预算 | `80000` |
| `MEMORY_INJECT_MAX_CHARS` | 注入块总长上限 | `12000` |
| `MEMORY_INGEST_DRY_RUN` | 仅日志不写盘 | `false` |

**默认 LLM 解析优先级**（逐项：base URL / API Key / 模型）：与知识库控制台 Agent 对齐 — `MEMORY_LLM_*` → 项目所属**业务线在 DB 中持久化的默认** OpenAI/Codex 兼容 Agent 工具配置（sanitize 后与执行层同源）→ 进程环境 `OPENAI_BASE_URL`、`OPENAI_API_KEY`、`OPENAI_MODEL`（模型仍可最终回落到 `gpt-4o-mini`）。实现见 `backend/src/agent-execution/agent-tool-openai-compatible-llm-credentials.service.ts` 与 `MemoryHostService.mergeRuntimeConfigForProject`。推荐生产只配置 Agent 控制台与可选 `OPENAI_*`，无须再重复配置 `MEMORY_LLM_*`。

完整键名与权重见 `backend/src/memory/memory-runtime.config.ts` 与方案第 11.2 节。

## 3. 插拔方式

- **关闭能力**：将 `MEMORY_EXTRACTION_ENABLED` 或 `MEMORY_INJECTION_ENABLED` 设为 `false`（或 `0`/`false` 字符串）。主执行路径不依赖二者。
- **更换实现**：保持同仓注册表约定，将对应 `MEMORY_*_PLUGIN_ID` 改为你的插件 id，并在 `MemoryModule` 启动时 `register` 该实现（见下节）。
- **未配置可用 LLM**（任一来源解析后 Base URL 仍为空）：沉淀管线在提取/补丁 LLM 阶段不会落盘（任务作业仍可能标记完成，表示已处理但无写入）。

## 4. 自定义插件

### 4.1 接口

- **ingest**：实现 `MemoryIngestPlugin`，`id` + `onTaskDone(job, caps)`。唯一写库须通过 `HostCapabilities.writeDoc`（相对路径仅允许 `memory/` 前缀）。
- **inject**：实现 `MemoryInjectPlugin`，`id` + `build(ctx, caps) => { text }`。

### 4.2 注册

在 `MemoryPluginRegistrationService`（或自定义模块启动逻辑）中：

```typescript
this.ingestRegistry.register(myIngestPlugin);
this.injectRegistry.register(myInjectPlugin);
```

### 4.3 宿主能力 `HostCapabilities`

实现侧见 `backend/src/memory/memory.types.ts` 与 `MemoryHostService`：`readDoc` / `writeDoc`、`completeJson`（OpenAI 兼容 JSON）、`getTaskWorkspaceMeta`、`redact`、`config` 快照等。

## 5. 数据与作业

- **作业表**：`memory_ingest_jobs`（`idempotency_key` 唯一，`status`: pending / processing / done / failed）。
- **信号表**：`memory_fact_signals`（按 `projectId` + `dedupKey` 统计召回，用于非冷启动时的门限）。
- **幂等**：同一 `idempotencyKey` 不会重复入队；消费完成后由 Worker 将状态置为 `done`。

## 6. 安全与日志

- 写盘与注入前经 `redactMemoryText` 等规则处理；路径禁止 `..` 穿越，仅允许 `docs/memory/**`。
- 请勿在日志中输出完整 transcript 或候选池全文（实现上已避免）。

## 7. 排障

- 关键词：`memory_ingest_job_failed`、`memory_llm_extract_facts_fail`、`memory_patch_anchor_miss`。
- 检查 `memory_ingest_jobs.error` 与 `status`。
- 注入无内容：确认 `docs/memory/` 存在且含 `.md`；`_routing.yaml` 可选。

## 8. 代码入口

- 模块：`backend/src/memory/memory.module.ts`
- 默认插件：`backend/src/memory/plugins/`
- Runner 注入拼接：`backend/src/agent-execution/runner-agent-execution.service.ts`
- 任务 `done` 入队：`backend/src/tasks/application/task-status.service.ts`
