## 🎯 核心特点

### 为什么小程序不需要构建？

```
传统 Web 项目:
  开发 → npm run build → dist/ → 上传服务器 → nginx 部署 → 访问 URL

小程序项目:
  开发 → make app-preview → 扫码预览 ✅
```

**关键差异**:
- Taro CLI 在执行 CI 命令时会**自动编译**代码
- 编译产物直接通过微信 CI 上传，无需手动构建
- 验证方式是扫描二维码，不是访问 URL
- 无需服务器部署

### 工作原理

```
make app-preview
    ↓
pnpm ci:weapp:preview (package.json)
    ↓
taro build --type weapp --preview (Taro CLI)
    ↓
自动编译 + 调用 CI 插件 (@tarojs/plugin-mini-ci)
    ↓
使用 miniprogram-ci SDK 上传代码
    ↓
微信 CI 服务器生成预览二维码
    ↓
扫码体验
```

## 🚀 快速上手

### 第一次使用（需配置私钥）

```bash
# 1. 检查配置
make app-check-key

# 2. 如果显示"私钥文件不存在"，按照提示配置：
#    - 从微信公众平台下载私钥
#    - 放到 ainative-app/key/ 目录

# 3. 再次检查，确保显示 ✓
make app-check-key

# 4. 生成预览二维码
make app-preview
```

### 日常使用（已配置私钥）

```bash
# 修改小程序代码后，直接执行：
make app-preview

# 扫描生成的二维码，立即查看效果
```

## 🎓 重要概念

### 1. 无需构建
小程序项目**不需要执行** `npm run build` 或类似的构建命令。Taro CLI 在执行 CI 命令时会自动处理编译。

### 2. 两种验证方式

**方式 1: 预览二维码（推荐）**
- 命令: `make app-preview`
- 优点: 最快速，无需微信后台操作
- 适用: 日常开发验证

**方式 2: 上传体验版**
- 命令: `make app-upload-test`
- 优点: 可以分享给多人测试
- 适用: 提交测试版本

### 3. 多环境支持

| 环境 | 命令 | 配置文件 | AppID |
|------|------|---------|-------|
| 测试/开发 | `make app-upload-test` | `ci.test.config.js` | wx60377e5c4f19d3be |
| 预发布 | `make app-upload-stage` | `ci.config.js` | wx003545950d54d0e3 |
| 生产 | `make app-upload-prod` | `ci.config.js` | wx003545950d54d0e3 |

## ⚠️ 注意事项

1. **私钥安全**
   - ✅ 私钥文件已在 `.gitignore` 中，不会提交到 Git
   - ❌ 不要分享私钥文件
   - ❌ 不要上传到公共平台

2. **命令执行位置**
   - ✅ 在项目根目录 (`yanxue-main/`) 执行 `make` 命令
   - ❌ 不要在 `ainative-app/` 目录内执行 `make` 命令

3. **开发者工具**
   - 首次使用需要开启"服务端口"
   - 预览命令需要开发者工具在后台运行

4. **权限要求**
   - 需要微信公众平台的开发者或管理员权限
   - 上传前确保有对应小程序的权限

## 🔧 故障排查

### 问题 1: 私钥文件不存在

```bash
# 诊断
make app-check-key

# 解决
# 1. 从微信公众平台下载私钥
# 2. 放到 ainative-app/key/ 目录
# 3. 再次检查
make app-check-key
```

### 问题 2: 连接失败 (ECONNREFUSED)

```bash
# 原因: 微信开发者工具未开启服务端口

# 解决:
# 1. 打开微信开发者工具
# 2. 设置 → 安全设置 → 开启"服务端口"
```

### 问题 3: 没有权限 (no permission)

```bash
# 原因: 当前微信账号无上传权限

# 解决:
# 1. 登录微信公众平台
# 2. 成员管理 → 添加为开发者
# 3. 确认权限后重试
```
