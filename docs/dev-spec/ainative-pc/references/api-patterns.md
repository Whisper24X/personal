# API 与数据访问规范

当前项目未内置统一请求封装，若需要对接后端，请先建立统一的数据访问层，避免在视图组件中直接调用 `fetch` 或第三方请求库。

## 目录建议
- `src/api/` - 接口函数定义（与后端接口一一对应）
- `src/services/` - 业务聚合与数据整理（可选）
- `src/types/` - 接口类型与 DTO 定义（可选）

## 基本约定
- API 函数保持纯粹，负责参数与路径拼装，不处理 UI 逻辑
- 错误处理与状态归一在请求封装中完成，避免在每个页面重复逻辑
- 请求基地址与环境相关配置通过 `.env` 提供，统一从 `import.meta.env` 读取

## 代码组织建议
- 以业务域分文件，例如 `src/api/user.ts`、`src/api/order.ts`
- 页面通过 `services` 或 `api` 调用，不直接拼装 URL
