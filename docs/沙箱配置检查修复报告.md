## ❌ 发现的问题

### 问题 1: entrypoint.sh 缺少数据库创建步骤 🔴 **高优先级**

**症状**:
- 首次启动沙箱时不会自动创建业务数据库
- 后端服务可能因为数据库不存在而启动失败
- init.sql 脚本可能执行到错误的数据库

**原因**:
`yanxue-main` 的 `entrypoint.sh` 缺少了创建数据库的步骤。

**修复内容**:
```bash
# 创建业务数据库
echo "[INIT] Creating database ${DB_NAME:-postgres}..."
su -s /bin/sh postgres -c "psql -c \"CREATE DATABASE ${DB_NAME:-postgres} OWNER ${DB_USER:-postgres};\"" 2>/dev/null || echo "[INFO] Database already exists"
echo "[INIT] Database ${DB_NAME:-postgres} ready"

# 更新 init.sql 执行命令，指定数据库
if [ -f "/workspace/ainative-backend/doc/sql/init.sql" ]; then
    echo "[INIT] Running init.sql..."
    su -s /bin/sh postgres -c "psql -d ${DB_NAME:-postgres} -f /workspace/ainative-backend/doc/sql/init.sql"
fi
```

**状态**: ✅ **已修复**

---

### 问题 2: supervisord.conf 缺少 app 服务配置 🟡 **中优先级**

**症状**:
- 小程序 H5 服务不会自动启动
- 无法通过沙箱访问 `/app/` 路径
- 只能手动启动 app 开发服务器

**原因**:
`supervisord.conf` 中只配置了 `backend` 和 `shadow`，缺少 `app` 服务。

**修复内容**:
```ini
[program:app]
command=/bin/bash -c "cd /workspace/ainative-app && pnpm install && pnpm dev:h5"
directory=/workspace/ainative-app
environment=TARO_APP_API="/api"
autostart=true
autorestart=true
startsecs=10
startretries=3
priority=120
stdout_logfile=/dev/stdout
stdout_logfile_maxbytes=0
stderr_logfile=/dev/stderr
stderr_logfile_maxbytes=0
```

同时更新了服务组配置：
```ini
[group:services]
programs=backend,shadow,app
priority=100
```

**额外修复**: 简化了 shadow 的启动命令，与参考项目保持一致：
```ini
# 修复前
command=/bin/bash -c "cd /workspace/ainative-shadow && export CI=true && pnpm install && pnpm exec rsbuild dev --env-mode development"
environment=CI="true",VITE_BASE_URL="/shadow/",VITE_API_URL="/api"

# 修复后
command=/bin/bash -c "cd /workspace/ainative-shadow && pnpm install && pnpm dev"
environment=VITE_BASE_URL="/shadow/",VITE_API_URL="/api"
```

**状态**: ✅ **已修复**

### 问题 3: nginx.conf 缺少 /app/ 路由配置 🟡 **中优先级**

**症状**:
- 访问 `http://localhost:8070/app/` 返回 404
- 无法通过统一入口访问小程序 H5
- 首页只显示 2 个服务链接

**原因**:
`nginx.conf` 中只配置了 `/api/` 和 `/shadow/` 的代理，缺少 `/app/` 配置。

**修复内容**:
```nginx
# 移动端 H5（App）
location /app/ {
    proxy_pass http://0.0.0.0:8200/app/;
    proxy_http_version 1.1;
    proxy_set_header Upgrade $http_upgrade;
    proxy_set_header Connection $connection_upgrade;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
}
```

**首页更新**: 从 2 列布局改为 3 列布局，添加 App 链接：
```html
<!-- 修复前：grid-template-columns: repeat(2,1fr) -->
<!-- 修复后：grid-template-columns: repeat(3,1fr) -->

<div class="links">
  <a href="/app/" target="_blank">App</a>
  <a href="/shadow/" target="_blank">Shadow</a>
  <a href="/api/" target="_blank">Backend</a>
</div>
```

**状态**: ✅ **已修复**

## ⚠️ 注意事项

### 1. 数据库名称差异

`yanxue-main` 的 Dockerfile 中数据库名设置为 `postgres`：
```dockerfile
ENV DB_NAME=postgres
```

而 `ainative-workspace` 使用 `ainative_backend`：
```dockerfile
ENV DB_NAME=ainative_backend
```

**建议**: 
- 如果后端代码中硬编码了数据库名，需要检查并调整
- 或者修改 Dockerfile 中的 `DB_NAME` 环境变量

### 2. Shadow 启动命令

从复杂命令简化为标准命令：
```bash
# 旧: export CI=true && pnpm install && pnpm exec rsbuild dev --env-mode development
# 新: pnpm install && pnpm dev
```

**检查点**:
- 确认 `ainative-shadow/package.json` 中有 `dev` 脚本
- 如果需要 CI=true 环境变量，可以在 environment 中指定

### 3. App 服务端口

App 服务使用端口 8200，确保：
- Taro 配置中的 H5 devServer 端口为 8200
- 或者在 `ainative-app/config/index.ts` 中配置：
  ```typescript
  h5: {
    devServer: {
      port: 8200
    }
  }
  ```
