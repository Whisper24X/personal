# 沙箱配置说明

## 🏷️ 环境区分

### 自动检测

环境通过**本机 IP** 自动判断，无需手动设置：

```
本机 IP == SANDBOX_IP_TEST (10.8.8.152)       → test 环境
本机 IP == SANDBOX_IP_STAGE                    → stage 环境
本机 IP == SANDBOX_IP_PRODUCTION               → production 环境
都不匹配                                       → development 环境
```

在 `sandbox/.env` 中配置 IP 映射：

```bash
SANDBOX_IP_TEST=10.8.8.152
#SANDBOX_IP_STAGE=
#SANDBOX_IP_PRODUCTION=
```

也可以手动强制指定（优先级最高）：

```bash
SANDBOX_ENV=test    # 设值则跳过 IP 检测，强制使用
```

### 环境对照表

| 环境 | SANDBOX_ENV | 容器内 DB/Redis | 后端配置 | 访问地址 |
|------|-------------|----------------|---------|---------|
| 开发 | `development` | 启动 | `development.yaml` | 自动检测 IP:PORT |
| 测试 | `test` | 启动 | `test.yaml` | device-test.local.yc345.tv |
| 预发 | `stage` | 不启动 | `stage.yaml` | device-stage.local.yc345.tv |
| 生产 | `production` | 不启动 | `production.yaml` | device.local.yc345.tv |

## 📋 端口映射架构

### 外部访问

通过 `SANDBOX_BASE_URL_<ENV>` 和 `SANDBOX_PORT` 环境变量配置

```
外部访问:  根据 SANDBOX_ENV 自动选择对应的 SANDBOX_BASE_URL_<ENV>
Docker:    主机端口 ${SANDBOX_PORT}  →  容器内部端口 8080
```

- `SANDBOX_BASE_URL_DEVELOPMENT`: 开发环境访问地址，留空自动拼接 `http://<本机IP>:<SANDBOX_PORT>`
- `SANDBOX_BASE_URL_TEST`: 测试环境访问地址
- `SANDBOX_BASE_URL_STAGE`: 预发环境访问地址
- `SANDBOX_BASE_URL_PRODUCTION`: 生产环境访问地址
- `SANDBOX_PORT`: Docker 端口映射的主机端口，默认 8070

### 内部服务端口（容器内固定）

| 服务 | 容器内端口 | 说明 |
|------|-----------|------|
| Nginx Gateway | 8080 | 主入口（映射到主机 SANDBOX_PORT） |
| Backend API | 8000 | Go 后端服务 |
| Shadow | 8100 | 管理后台 |
| App QRCode | 8200 | 小程序二维码页面 |
| PostgreSQL | 5432 | 数据库 |
| Redis | 6379 | 缓存 |

## 🔧 配置方式

### 方法 1: 修改 .env 文件（推荐）

编辑 `sandbox/.env`:

```bash
# 运行环境: development | test | stage | production
SANDBOX_ENV=development

# 各环境的外部访问地址（留空自动拼接 IP:PORT）
SANDBOX_BASE_URL_DEVELOPMENT=
SANDBOX_BASE_URL_TEST=http://device-test.local.yc345.tv
SANDBOX_BASE_URL_STAGE=http://device-stage.local.yc345.tv
SANDBOX_BASE_URL_PRODUCTION=http://device.local.yc345.tv

# Docker 端口映射（多实例时必须不同）
SANDBOX_PORT=8070
```

### 方法 2: 命令行临时切换环境

```bash
SANDBOX_ENV=test make sandbox-restart
```

## 🔄 Docker 端口映射

### sandbox.sh 中的配置

```bash
# 容器配置（优先级：命令行环境变量 > .env 文件 > 默认值）
NGINX_PORT="${SANDBOX_PORT:-8080}"

# Docker 运行命令
docker run -d \
    --name "$CONTAINER_NAME" \
    -p "${NGINX_PORT}:8080" \
    -e "SANDBOX_BASE_URL=${SANDBOX_BASE_URL_RESOLVED}" \
    ...
```

**说明**:
- `-p "${NGINX_PORT}:8080"` 将主机的 `${NGINX_PORT}` 映射到容器内的 8080
- 容器内服务始终监听 8080（固定）
- 如果通过外部反向代理（如 Nginx）访问，`SANDBOX_PORT` 仅用于 Docker 映射，外部 URL 由 `SANDBOX_BASE_URL` 控制

## 📊 端口使用场景

### 场景 1: 域名访问（推荐）

**配置**:
```bash
SANDBOX_BASE_URL=http://device-test.local.yc345.tv
SANDBOX_PORT=8070
```

```
外部用户  →  域名解析 + 反向代理(80)  →  主机:8070  →  容器:8080 (Nginx)
                                                          ├→ 8000 (Backend)
                                                          ├→ 5176 (Shadow)
                                                          └→ 8200 (App)
```

### 场景 2: IP + 端口直连

**配置**: `SANDBOX_PORT=8070`（`SANDBOX_BASE_URL` 留空）

```
主机                      容器
8070  ←→  8080 (Nginx)
              ├→ 8000 (Backend)
              ├→ 5176 (Shadow)
              └→ 8200 (App)
```

### 场景 3: 多实例（避免冲突）

**项目 A (yanxue-main)**: `SANDBOX_PORT=8070`
```
主机: 8070 → 容器 A: 8080
```

**项目 B (ainative-workspace)**: `SANDBOX_PORT=8080`
```
主机: 8080 → 容器 B: 8080
```

两个沙箱可以同时运行，互不干扰！

## ⚠️ 注意事项

### 1. 容器内端口固定

容器内的服务端口是固定的（8080, 8000, 8100, 8200 等），**不要修改**。

只有主机端口（`SANDBOX_PORT`）和外部访问地址（`SANDBOX_BASE_URL`）可以配置。

### 2. 端口冲突

如果启动失败，检查端口是否被占用：

```bash
# macOS/Linux
lsof -i :8070

# 或使用 netstat
netstat -an | grep 8070
```

解决方法：
- 停止占用端口的程序
- 或修改 `SANDBOX_PORT` 为其他端口

### 3. 防火墙配置

确保主机防火墙允许访问 `SANDBOX_PORT`。

### 4. 容器重启

修改配置后需要重启沙箱：

```bash
make sandbox-restart
```

或

```bash
./sandbox/sandbox.sh restart
```

## 🐛 故障排查

### 问题 1: 无法访问服务

**检查端口映射**:
```bash
docker port yanxue-main-sandbox
```

应该看到类似输出：
```
8080/tcp -> 0.0.0.0:8070
```

### 问题 2: 端口已被占用

**错误信息**:
```
Error: bind: address already in use
```

**解决**:
1. 查找占用端口的进程：
   ```bash
   lsof -i :8070
   ```

2. 停止该进程或修改 `SANDBOX_PORT`

### 问题 3: 环境变量未生效

**检查加载顺序**:

优先级（从高到低）：
1. 命令行环境变量
2. `.env` 文件
3. 默认值（8080）

**验证**:
```bash
# 查看实际使用的端口
docker ps | grep sandbox
```

## 📚 总结

### 关键点

1. **环境区分**: 通过 `SANDBOX_ENV` 切换运行环境
2. **development / test**: 启动容器内 PostgreSQL + Redis
3. **stage / production**: 不启动内部 DB/Redis，连接外部数据库
4. **容器内端口固定**: Nginx 始终监听 8080
5. **外部地址可配置**: 通过 `SANDBOX_BASE_URL` 设置完整访问地址
6. **Docker 端口可配置**: 通过 `SANDBOX_PORT` 设置主机端口映射
7. **多实例支持**: 不同项目使用不同的 `SANDBOX_PORT`

### 最佳实践

- ✅ 通过 `SANDBOX_ENV` 区分开发和线上环境
- ✅ 为每个环境配置对应的 `SANDBOX_BASE_URL_<ENV>`
- ✅ 切换环境后执行 `make sandbox-restart`
- ✅ 多项目使用不同端口避免冲突
- ✅ 通过 `./sandbox/sandbox.sh info` 查看当前环境和访问地址
