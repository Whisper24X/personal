# 版本审查功能使用指南

## 功能概述

版本审查功能通过5轮交互式提问帮助用户检查版本想法与系统核心逻辑的一致性。支持前端 API 交互模式，使用状态机管理审查流程。

**技术说明**：

- **问题生成和文档生成**：使用 **Cursor CLI 工具**，可在任何环境下运行
- **用户交互**：通过 **前端 API 端点**进行，支持轮询状态和提交答案
- **状态管理**：审查状态存储在数据库 `project_versions.metadata` 字段中

每轮提问基于：

- 用户输入的版本想法（idea）
- 关联的知识库信息（业务规则、历史PRD/MRD、技术约束等）
- 之前轮次的用户回答
- CLI工具生成的问题（通过version-review skill指导）

## 启用方式

### 默认行为

版本审查功能**默认启用**，但需要前端主动调用 API 端点启动审查流程。

### 环境变量配置（可选）

如果需要禁用或调整行为，可以在 `.env` 文件中添加以下配置：

```bash
# 禁用版本审查功能（默认：启用）
ENABLE_VERSION_REVIEW=false
```

### 配置说明

- `ENABLE_VERSION_REVIEW`: 设置为 `false` 时，会禁用版本审查功能（默认：启用）

## API 端点

### 1. 启动审查

**POST** `/api/projects/:id/versions/:versionId/review/start`

启动版本审查流程，初始化审查状态并生成第一轮问题。

**响应**：

```json
{
  "success": true,
  "data": {
    "status": "generating_question",
    "currentRound": 1,
    "message": "审查已启动，正在生成第一轮问题..."
  }
}
```

### 2. 获取审查状态

**GET** `/api/projects/:id/versions/:versionId/review/status`

获取当前审查状态，包括当前问题、已回答的问题等。

**响应**：

```json
{
  "success": true,
  "data": {
    "status": "waiting_answer",
    "currentRound": 1,
    "totalRounds": 5,
    "currentQuestion": {
      "question": "问题内容...",
      "questionType": "business_rules"
    },
    "questionsAndAnswers": [
      {
        "question": "问题1",
        "answer": "答案1",
        "questionType": "business_rules"
      }
    ],
    "reviewDocumentPath": null,
    "error": null
  }
}
```

**状态说明**：

- `pending`: 待开始
- `generating_question`: 正在生成问题
- `waiting_answer`: 等待用户回答
- `generating_document`: 正在生成文档
- `completed`: 已完成
- `failed`: 失败

### 3. 提交答案

**POST** `/api/projects/:id/versions/:versionId/review/answer`

提交用户答案，系统会自动生成下一轮问题或生成审查文档。

**请求体**：

```json
{
  "answer": "用户答案内容"
}
```

**响应**：

```json
{
  "success": true,
  "data": {
    "status": "generating_question",
    "currentRound": 2,
    "message": "答案已提交，正在生成下一轮问题..."
  }
}
```

### 4. 继续审查（可选）

**POST** `/api/projects/:id/versions/:versionId/review/continue`

手动触发下一轮问题生成（通常不需要，因为 `submitAnswer` 会自动触发）。

## 工作流程

### 1. 版本创建

用户在创建版本时输入版本想法（idea字段）：

```json
POST /api/projects/:id/versions
{
  "versionName": "v1.0",
  "idea": "添加用户登录功能",
  "description": "实现用户认证和授权"
}
```

### 2. 启动审查

前端调用启动审查 API：

```javascript
// 启动审查
const response = await fetch('/api/projects/proj-123/versions/version-456/review/start', {
  method: 'POST',
});

const data = await response.json();
// data.data.status 为 "generating_question"
```

### 3. 轮询状态

前端定期轮询审查状态，检查当前状态：

```javascript
// 轮询状态
const pollStatus = async () => {
  const response = await fetch('/api/projects/proj-123/versions/version-456/review/status');
  const data = await response.json();

  if (data.data.status === 'waiting_answer') {
    // 显示当前问题，等待用户输入
    displayQuestion(data.data.currentQuestion);
  } else if (data.data.status === 'completed') {
    // 审查完成，显示结果
    displayReviewComplete(data.data);
    stopPolling();
  } else if (data.data.status === 'failed') {
    // 审查失败，显示错误
    displayError(data.data.error);
    stopPolling();
  }
};

// 每2秒轮询一次
const interval = setInterval(pollStatus, 2000);
```

### 4. 提交答案

当状态为 `waiting_answer` 时，用户输入答案并提交：

```javascript
// 提交答案
const submitAnswer = async (answer) => {
  const response = await fetch('/api/projects/proj-123/versions/version-456/review/answer', {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ answer }),
  });

  const data = await response.json();
  // 答案已提交，继续轮询状态
};
```

### 5. 重复步骤 3-4

重复轮询和提交答案，直到5轮全部完成。

### 6. 生成审查文档

最后一轮完成后，系统会自动生成审查文档，状态变为 `completed`。

## 5轮提问说明

### 第1轮：业务规则冲突检查

**知识来源**：业务规则库（`docs/business-knowledge/`）

**检查内容**：

- 版本想法是否与现有业务规则冲突
- 是否需要调整想法以符合业务规则
- 提供具体的冲突示例

### 第2轮：功能冲突检查

**知识来源**：历史PRD、功能清单

**检查内容**：

- 版本想法是否与现有功能重复或冲突
- 是否需要调整功能范围
- 提供具体的功能对比

### 第3轮：术语一致性检查

**知识来源**：术语词典

**检查内容**：

- 版本想法中使用的术语是否与系统定义一致
- 列出可能不一致的术语
- 询问是否需要统一术语使用

### 第4轮：数据模型一致性检查

**知识来源**：技术约束、开发规范

**检查内容**：

- 版本想法是否涉及数据模型变更
- 指出可能的技术约束
- 询问是否需要调整需求以符合技术规范

### 第5轮：综合确认

**知识来源**：综合前4轮的知识和回答

**检查内容**：

- 总结前面讨论的关键点
- 询问是否需要基于讨论结果调整版本想法
- 如果用户需要调整，询问具体的调整方向

## 审查文档格式

生成的审查文档包含以下内容：

1. **版本信息**
   - 版本名称
   - 版本想法
   - 生成时间

2. **问答记录**
   - 5轮问题和用户回答的完整记录

3. **修改建议**
   - 冲突分析
   - 修改建议（针对每个冲突）
   - 行动项清单

文档保存在：

```
workspace/{applicationId}/{projectId}/versions/{versionId}/ainative-workspace/docs/version-review/{versionName}-review.md
```

## 状态机说明

审查流程使用状态机管理，状态转换如下：

```
pending → generating_question → waiting_answer → generating_question → ... → generating_document → completed
                                                                                    ↓
                                                                                 failed
```

- **pending**: 初始状态，审查尚未启动
- **generating_question**: 正在通过 Cursor CLI 工具生成问题
- **waiting_answer**: 问题已生成，等待用户提交答案
- **generating_document**: 所有问题已完成，正在生成审查文档
- **completed**: 审查完成，文档已生成
- **failed**: 审查过程中出现错误

## 注意事项

1. **异步处理**：问题生成和文档生成是异步的，需要前端轮询状态
2. **状态持久化**：所有状态存储在数据库 `metadata` 字段，确保服务重启后状态不丢失
3. **错误处理**：如果生成失败，状态变为 `failed`，前端显示错误信息
4. **幂等性**：`startReview` 是幂等的，如果审查已启动，返回当前状态
5. **自动继续**：提交答案后会自动生成下一轮问题，无需手动调用 `continue`

## 示例

### 完整的前端交互流程

```javascript
// 1. 启动审查
async function startReview(projectId, versionId) {
  const response = await fetch(`/api/projects/${projectId}/versions/${versionId}/review/start`, {
    method: 'POST',
  });
  return await response.json();
}

// 2. 轮询状态
function pollReviewStatus(projectId, versionId, onUpdate, onComplete, onError) {
  const interval = setInterval(async () => {
    try {
      const response = await fetch(`/api/projects/${projectId}/versions/${versionId}/review/status`);
      const data = await response.json();

      if (data.success && data.data) {
        const status = data.data.status;

        if (status === 'waiting_answer') {
          // 显示问题，等待用户输入
          onUpdate(data.data);
        } else if (status === 'completed') {
          // 审查完成
          clearInterval(interval);
          onComplete(data.data);
        } else if (status === 'failed') {
          // 审查失败
          clearInterval(interval);
          onError(data.data.error);
        }
        // generating_question 和 generating_document 状态继续轮询
      }
    } catch (error) {
      clearInterval(interval);
      onError(error.message);
    }
  }, 2000); // 每2秒轮询一次

  return interval;
}

// 3. 提交答案
async function submitAnswer(projectId, versionId, answer) {
  const response = await fetch(`/api/projects/${projectId}/versions/${versionId}/review/answer`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ answer }),
  });
  return await response.json();
}

// 使用示例
async function handleReview(projectId, versionId) {
  // 启动审查
  await startReview(projectId, versionId);

  // 开始轮询
  const interval = pollReviewStatus(
    projectId,
    versionId,
    (data) => {
      // 显示当前问题
      console.log('当前问题:', data.currentQuestion.question);
    },
    (data) => {
      // 审查完成
      console.log('审查完成，文档路径:', data.reviewDocumentPath);
    },
    (error) => {
      // 错误处理
      console.error('审查失败:', error);
    }
  );

  // 用户提交答案时
  async function onUserSubmitAnswer(answer) {
    await submitAnswer(projectId, versionId, answer);
    // 继续轮询，状态会自动更新
  }
}
```

## 故障排查

### 审查未启动

1. 检查 `ENABLE_VERSION_REVIEW` 环境变量是否被设置为 `false`
2. 检查项目是否有 `applicationId`
3. 检查版本是否有 `idea` 字段
4. 检查日志中是否有相关错误信息

### 状态轮询无响应

1. 检查 API 端点是否正确
2. 检查版本 ID 是否正确
3. 检查网络连接
4. 查看浏览器控制台错误信息

### 知识库检索失败

1. 检查项目是否关联了知识库
2. 检查知识库文档是否存在
3. 查看日志中的错误信息

### 审查文档未生成

1. 检查版本是否有 `applicationId`
2. 检查工作空间路径是否正确
3. 检查文件系统权限
4. 查看日志中的错误信息
