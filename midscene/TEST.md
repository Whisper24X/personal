## 第二部分：测试用例

### 用例编写规范

#### 优先级定义

| 优先级 | 定义     | 说明                       |
| ------ | -------- | -------------------------- |
| P0     | 核心功能 | 主流程、核心业务，必须通过 |
| P1     | 重要功能 | 重要分支、常用功能         |
| P2     | 一般功能 | 边界条件、异常处理         |
| P3     | 低优先级 | 极端场景、优化建议         |

#### 用例格式说明

- 采用 **Given-When-Then** 格式（BDD风格）
- **Given**：前置条件和测试数据准备
- **When**：执行的操作步骤（含具体导航路径，可直接映射为 Playwright action）
- **Then**：预期结果验证（仅页面可观测结果，可直接映射为 Playwright assertion）

### 模块1：CSV 映射配置

#### TC-001：CSV 映射配置弹窗存在「其他」Tab 并可切换 - 正向场景

| 属性     | 值                             |
| -------- | ------------------------------ |
| 用例ID   | TC-CSV-001                     |
| 类型     | 管理后台                       |
| 优先级   | P0                             |
| 前置条件 | 用户已登录管理后台，具有渠道订单管理权限 |
| 关联需求 | PRD-功能1                      |

**Given**：

- 已通过账号密码登录管理后台
- 渠道订单管理页可正常访问

**When**：

- 侧栏点击「订单管理」→ 等待子菜单展开 → 点击子菜单「渠道订单管理」→ 等待订单列表表格加载
- 在渠道订单管理页点击「CSV映射配置」按钮 → 等待映射配置弹窗打开
- 在映射配置弹窗中点击「其他」Tab → 等待 Tab 切换完成、映射表单加载

**Then**：

- 映射表单区域包含「系统字段与CSV文件字段映射」「订单状态值映射」「服务状态值映射」三个配置区块

**元素选择**：

| 元素 | 类型 | 参数 | 定位 |
| --- | --- | --- | --- |
| 订单管理 | 侧栏一级菜单 | 文本=订单管理 | getByRole/locator |
| 渠道订单管理 | 侧栏子菜单 | 文本=渠道订单管理 | getByRole/locator |
| CSV映射配置按钮 | 按钮 | 文本=CSV映射配置 | getByRole('button') |
| 其他 Tab | Tab | 文本=其他 | .el-tabs__item filter hasText |
| 映射配置弹窗 | 对话框 | 标题=CSV文件映射配置 | getByRole('dialog') |

#### TC-002：「其他」Tab 下配置映射并保存成功 - 正向场景

| 属性     | 值                             |
| -------- | ------------------------------ |
| 用例ID   | TC-CSV-002                     |
| 类型     | 管理后台                       |
| 优先级   | P0                             |
| 前置条件 | 已打开 CSV 映射配置弹窗并切换到「其他」Tab |
| 关联需求 | PRD-功能1                      |

**Given**：

- 已通过账号密码登录管理后台
- 渠道订单管理页可正常访问

**When**：

- 侧栏点击「订单管理」→ 等待子菜单展开 → 点击子菜单「渠道订单管理」→ 等待订单列表表格加载
- 在渠道订单管理页点击「CSV映射配置」按钮 → 等待弹窗打开 → 点击「其他」Tab → 等待映射表单加载
- 在新行中：在「系统字段」列的下拉框中选择「支付时间」，在「CSV文件字段」列输入「channel_name」
- 在新行中：在订单状态值-系统状态值 列的下拉框中选择「支付时间」，在「CSV文件字段」列输入「channel_name」
- 在新行中：在服务状态值映射-系统状态值 列的下拉框中选择「待预约」，在「CSV文件字段」列输入「channel_name」
- 点击「保存」按钮 → 等待保存成功提示、弹窗关闭
- 再次点击「CSV映射配置」按钮 → 等待弹窗打开 → 点击「其他」Tab → 等待映射表单加载

**Then**：

- 出现保存成功提示
- 映射配置弹窗内「其他」Tab 的系统字段映射表中

**元素选择**：

| 元素 | 类型 | 参数 | 定位 |
| --- | --- | --- | --- |
| 添加字段映射按钮 | 按钮 | 文本=添加字段映射 | .el-tab-pane[aria-hidden="false"] 内 getByRole('button') |
| 系统字段下拉框 | 表单项+下拉框 | 系统字段列内 | .el-tab-pane[aria-hidden="false"] .el-table .el-select |
| 下拉选项「三方渠道」 | 下拉选项 | 文本=三方渠道 | getByRole('listbox').getByRole('option', { name: '三方渠道' }) |
| 添加状态映射按钮 | 按钮 | 文本=添加状态映射 | .el-tab-pane[aria-hidden="false"] 内 getByRole('button')，有两处需按区域区分 |
| 保存按钮 | 按钮 | 文本=保存 | getByRole('button') |
| 成功提示 | 成功提示 | — | .el-message--success |

## 附录：测试用例生成指南

### 强制要求

1. **用例覆盖完整性**：
   - 必须覆盖PRD中所有功能点
   - 必须包含正向场景和异常场景
   - 必须包含边界条件测试

2. **用例格式规范**：
   - 统一使用 Given-When-Then 格式
   - 每个用例必须有唯一ID
   - 每个用例必须标注优先级
   - 每个用例必须标注类型（适用端）

3. **测试数据要求**：
   - 测试数据必须具体、可执行
   - 不允许使用模糊描述如"某用户"
   - 必须包含边界值数据

4. **预期结果要求（Then）**：
   - Then 只写**用户在页面上可观测到的结果**（提示信息、列表变化、按钮状态等）
   - Then 断言的目标元素必须存在于 When 最后一步所在的页面上（When-Then 联动）
   - 每条 Then 需能映射为 Playwright 断言：元素可见、文本包含、元素状态变化
   - 禁止写数据库断言（如 `数据库中 xxx 字段已更新`）
   - 禁止写硬编码时间（如 `2秒内`），改为 `出现xxx提示`
   - 禁止写硬编码数量（如 `已成功设置 3 台`），改为 `出现成功数量反馈`
   - 禁止写接口级断言（如 `接口返回数据包含 xxx`）
   - 禁止写主观/不可验证描述（如 `便于快速找到xxx`）
   - 数据前提（设备数量、初始状态等）放在 Given 中，不放在 Then 中
   - 异常场景必须验证用户可见的错误提示

5. **操作步骤要求（When）**：
   - UI 用例的 When 必须包含具体的导航路径（菜单点击顺序），不使用抽象描述
   - 每步点击后标注等待点（如 → 等待表格加载、→ 等待子菜单展开）
   - 导航步骤用 → 连接，先写导航再写业务操作

6. **自动化可行性标注**：
   - 对于非 UI 可验证的用例（后台任务、cron job、数据库直接操作），在属性表 `类型` 列标注为 `通用（不可UI自动化）`

7. **用例数量要求**：
   - 每个功能模块至少3个测试用例
   - 包含：正向场景、边界条件、异常场景

### 输出格式要求

- 使用 Markdown 格式
- 严格按照测试文档模板结构
- 用例描述清晰、步骤可执行
