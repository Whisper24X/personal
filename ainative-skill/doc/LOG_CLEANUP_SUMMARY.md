# 日志管理功能实施总结

## 📌 问题描述

部署到服务器后发现目录及子目录下的 logs 文件过大会导致服务崩溃。

## ✅ 解决方案

实施自动化日志管理系统，设置日志文件总大小上限为 20GB，达到阈值后自动删除时间最久的日志文件。

## 🔧 实施内容

### 1. 核心脚本

#### `scripts/log-manager.js`

- 递归扫描多个日志目录（logs/、backend/logs/、frontend/logs/）
- 统计所有 .log 文件的总大小（跨所有目录）
- 当总大小超过 18GB (90% 阈值) 时触发清理
- 跨所有目录按文件修改时间排序，删除最旧的文件
- 清理至 14GB (70%) 以下后停止

#### `scripts/setup-log-cleanup-cron.sh`

- 一键设置 Cron 定时任务
- 自动配置每小时执行一次清理
- 适用于非 PM2 环境

### 2. 配置更新

#### `ecosystem.config.js`

- 新增 `log-cleanup` PM2 任务
- 配置每小时自动运行 (`cron_restart: '0 * * * *'`)
- 日志输出到 `logs/log-cleanup-out.log`

#### `package.json`

- 新增 `logs:cleanup` - 手动清理日志
- 新增 `logs:size` - 查看日志使用情况
- 新增 `logs:setup-cron` - 设置定时任务

### 3. 文档完善

#### `doc/LOG_MANAGEMENT.md`

- 完整的日志管理系统文档
- 配置说明、使用方法、故障排查
- 三种部署方式详细说明

#### `doc/LOG_CLEANUP_DEPLOY.md`

- 快速部署指南
- 应急处理方案
- 常见问题解答

#### `scripts/README.md`

- 更新脚本工具列表
- 添加日志管理工具说明

## 📊 技术参数

| 参数       | 值             | 说明                                 |
| ---------- | -------------- | ------------------------------------ |
| 总容量上限 | 20 GB          | 所有日志目录总大小的最大允许值       |
| 监控目录   | 3 个           | logs/、backend/logs/、frontend/logs/ |
| 清理阈值   | 18 GB (90%)    | 超过此值触发清理                     |
| 清理目标   | 14 GB (70%)    | 清理后保持的大小                     |
| 执行频率   | 每小时         | 自动检查频率                         |
| 清理策略   | 跨目录时间优先 | 从所有目录中删除最旧的文件           |

## 🚀 部署方式

### 方式 1: PM2（推荐）

```bash
# 重启服务即可自动启动日志清理任务
pm2 restart ecosystem.config.js

# 查看任务状态
pm2 list

# 查看清理日志
pm2 logs log-cleanup
```

**优点**:

- ✅ 自动管理，无需额外配置
- ✅ 统一的进程管理
- ✅ 便于监控和日志查看

### 方式 2: Cron

```bash
# 运行设置脚本
./scripts/setup-log-cleanup-cron.sh

# 验证
crontab -l
```

**优点**:

- ✅ 系统级定时任务
- ✅ 独立于应用进程
- ✅ 适用于非 PM2 环境

### 方式 3: 手动运行

```bash
# 随时可以手动执行
pnpm logs:cleanup
```

**用途**:

- 应急清理
- 测试验证
- 按需执行

## 📈 预期效果

### 问题解决

1. ✅ **防止磁盘满**: 所有日志目录总大小不会超过 20GB
2. ✅ **多目录监控**: 自动监控根目录、backend、frontend 的日志
3. ✅ **自动化管理**: 无需人工干预，自动清理
4. ✅ **智能清理**: 跨目录按时间优先删除，保留最新日志
5. ✅ **服务稳定**: 避免因磁盘满导致服务崩溃

### 性能影响

- CPU 占用: 极低
- 内存占用: < 50MB

### 维护成本

- 无需日常维护

4. ✅ **回滚支持**: 可随时停止清理任务
