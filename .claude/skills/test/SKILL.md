# 生成测试用例

基于 PRD 和系统设计文档生成测试用例，确保功能覆盖率和质量标准。

## ⚠️ 执行前必读（强制）

**在生成任何内容之前，必须先执行以下步骤：**

1. **读取模板文件**：使用 Read 工具读取 [test-template.md](references/test-template.md)
2. **理解模板结构**：模板仅包含测试用例部分，输出必须严格遵循此结构
3. **按模板格式输出**：每个测试用例必须使用 Given-When-Then 格式和属性表格

## 输出规范（强制）

> **重要**：以下规范必须严格遵守，不可违反。

| 项目           | 规范                                                                            |
| -------------- | ------------------------------------------------------------------------------- |
| **输出文件名** | `TEST.md`（必须使用此文件名，不可使用其他名称如"测试用例.md"）                  |
| **文件数量**   | 只生成 1 个文件，禁止创建额外的说明文件或拆分文件                               |
| **文档结构**   | 必须严格按照 [test-template.md](references/test-template.md) 仅包含测试用例部分 |
| **用例格式**   | 必须使用 Given-When-Then（BDD）格式，包含属性表格                               |

## 文档结构（必须严格遵循）

输出的 TEST.md 仅包含测试用例部分，标题格式必须一致：

```markdown
# 测试文档

---

## 第二部分：测试用例

（使用 Given-When-Then 格式，每个用例必须包含属性表格）
```

## 测试用例格式（必须严格遵循）

**每个测试用例必须使用以下格式，不得使用"测试步骤/预期结果"的传统格式：**

```markdown
#### TC-001：[用例标题] - [场景描述]

| 属性     | 值                             |
| -------- | ------------------------------ |
| 用例ID   | TC-[模块]-001                  |
| 类型     | Web端/App端/PC端/管理后台/通用 |
| 优先级   | P0                             |
| 前置条件 | [前置条件描述]                 |
| 关联需求 | PRD-[需求编号]                 |

**Given**：

- [系统状态/数据准备]
- [用户角色/权限]

**When**：

- [操作步骤]

**Then**：

- [预期结果验证]
```

## 核心原则

1. **测试覆盖完整性**：每个 PRD 功能点必须有对应的测试用例
2. **用例可执行性**：测试用例必须具体、可操作、可验证
3. **场景全面性**：包含正向场景、边界条件、异常场景
4. **格式统一性**：采用 Given-When-Then（BDD）格式，禁止使用"测试步骤/预期结果"传统格式
5. **类型必填**：每个测试用例必须填写「类型」，取值根据 PRD 覆盖端（Web、H5/App、PC、管理后台等）选择，多端适用可填「通用」

## 优先级定义

| 优先级 | 定义     | 说明                       |
| ------ | -------- | -------------------------- |
| P0     | 核心功能 | 主流程、核心业务，必须通过 |
| P1     | 重要功能 | 重要分支、常用功能         |
| P2     | 一般功能 | 边界条件、异常处理         |
| P3     | 低优先级 | 极端场景、优化建议         |

## 类型定义

| 类型     | 说明                      |
| -------- | ------------------------- |
| Web端    | 浏览器 Web 页面           |
| H5端     | 移动端 H5                 |
| App端    | 原生/混合 App             |
| PC端     | 桌面客户端                |
| 管理后台 | 后台管理系统 Web          |
| 通用     | 多端共用或接口/无 UI 区分 |

## 生成流程

### Step 1: 读取模板（必须执行）

**必须首先读取** [test-template.md](references/test-template.md) 获取测试用例部分的结构和编写规范。

### Step 2: 读取 PRD 文档

读取用户指定的 PRD 文件，提取：

- 功能模块清单与优先级
- 用户角色与权限矩阵
- 业务流程与状态转换
- 接口定义与数据模型
- 验收标准与 KPI 指标

### Step 3: 生成测试用例（第二部分）

依据模板第二部分生成测试用例，确保：

- 每个功能模块至少 3 个用例（正向、边界、异常）
- **必须使用 Given-When-Then 格式**
- **必须包含属性表格**（用例ID、类型、优先级、前置条件、关联需求）

### Step 4: 验收检查

- [ ] 文档仅包含测试用例部分，与模板一致
- [ ] 每个用例都有属性表格
- [ ] 每个用例都使用 Given-When-Then 格式
- [ ] 覆盖 PRD 所有 P0/P1 功能点
- [ ] 无模糊描述（如"某用户"、"正常显示"）

## 常见问题处理

| 情况               | 处理方式                       |
| ------------------ | ------------------------------ |
| PRD 验收标准不清晰 | 根据功能描述推导，标注需确认   |
| 接口文档不完整     | 基于 Design 推导，标注需补充   |
| 测试数据依赖复杂   | 明确数据准备步骤，列出依赖关系 |
| 性能指标未定义     | 填充合理默认值，标注需评审     |

## 禁止事项

以下行为是禁止的，违反将导致输出无效：

1. ❌ 使用非 `TEST.md` 的文件名（如"测试用例.md"、"test-cases.md"等）
2. ❌ 创建多个文件（如一个说明文件+一个用例文件）
3. ❌ 使用传统的"测试步骤/预期结果"格式替代 Given-When-Then
4. ❌ 输出测试计划、接口测试用例或测试数据（仅输出测试用例部分）
5. ❌ 用例缺少属性表格（用例ID、类型、优先级、前置条件、关联需求）
6. ❌ 不读取模板文件就直接生成内容
7. ❌ 自定义文档结构，不遵循模板的测试用例部分结构
