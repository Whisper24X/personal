# 2048 小游戏 — 产品需求文档（PRD）

> 版本：v1.0 | 日期：2026-03-03 | 状态：初版

---

## 1. 产品概述

### 1.1 产品背景

2048 是一款经典的数字益智类滑动游戏，玩家通过上下左右滑动将相同数字的方块合并，最终目标是合成 2048 方块。该游戏规则简单、上手快、具有高度成瘾性，适合碎片化时间娱乐。

### 1.2 产品目标

打造一款**有趣、流畅、视觉精美**的 Web 端 2048 小游戏，具备以下目标：

- 提供经典 2048 玩法，确保核心体验流畅
- 界面美观、动画丝滑，提升游戏趣味性
- 支持 PC 键盘操作和移动端触摸滑动
- 提供分数记录与最高分功能，增强可玩性

### 1.3 目标用户

| 用户群体 | 描述 |
|---------|------|
| 休闲游戏玩家 | 喜欢简单上手、碎片时间可玩的益智游戏 |
| 数字爱好者 | 喜欢数字策略类游戏的用户 |
| 所有年龄段 | 规则简洁，老少皆宜 |

### 1.4 产品定位

轻量级 Web 端单机益智小游戏，无需注册登录，打开即玩。

## 3. 功能详述

### 3.1 【F-01】核心游戏逻辑（P0）

**用户故事**：
> 作为一名玩家，我希望在 4×4 的棋盘上通过滑动操作合并相同数字方块，这样我可以不断挑战更高的数字。

**功能描述**：

1. **棋盘初始化**
   - 游戏启动时生成 4×4 的空棋盘
   - 随机在两个空格位置生成初始方块（90% 概率生成 2，10% 概率生成 4）

2. **方块滑动**
   - 玩家执行一次滑动操作（上/下/左/右），所有方块向该方向滑动
   - 方块滑动到碰到边界或其他方块时停止

3. **方块合并**
   - 同一方向上相邻且数值相同的两个方块合并为一个新方块，新方块数值 = 原数值 × 2
   - 每次滑动中，每个方块最多只能参与一次合并
   - 合并方向遵循滑动方向（如向左滑动，从左到右依次合并）

4. **新方块生成**
   - 每次有效滑动（棋盘状态发生变化）后，在随机空格位置生成一个新方块
   - 新方块数值：90% 概率为 2，10% 概率为 4

5. **得分计算**
   - 每次合并时，合并产生的新方块数值累加到当前分数
   - 例如：两个 16 合并 → 得 32 分

**验收标准**：
- [ ] 棋盘为 4×4 格子布局，初始时有 2 个随机方块
- [ ] 四个方向滑动均能正确移动和合并方块
- [ ] 相同数值方块碰撞时正确合并，数值翻倍
- [ ] 一次滑动中同一方块不会被多次合并（如 [2,2,2,2] 向左 → [4,4,0,0] 而非 [8,0,0,0]）
- [ ] 无效滑动（棋盘无变化）不生成新方块
- [ ] 合并时分数正确累加

---

### 3.2 【F-02】游戏操作（P0）

**用户故事**：
> 作为一名玩家，我希望在电脑上使用键盘方向键、在手机上通过触摸滑动来操控游戏，这样我可以在任何设备上畅玩。

**功能描述**：

1. **PC 端操作**
   - 监听键盘 `↑` `↓` `←` `→` 方向键
   - 可选支持 `W` `A` `S` `D` 键

2. **移动端操作**
   - 监听触摸滑动手势（touchstart / touchend 计算方向）
   - 滑动距离阈值 ≥ 30px 才触发操作
   - 根据水平/垂直方向的偏移量判断滑动方向

3. **操作防抖**
   - 动画执行期间忽略新操作，防止连续快速操作导致状态异常

**验收标准**：
- [ ] PC 端按下方向键可正确控制方块移动方向
- [ ] 移动端触摸滑动可正确识别四个方向
- [ ] 短距离误触（< 30px）不会触发操作
- [ ] 动画进行中的操作不会导致异常

---

### 3.3 【F-03】分数系统（P0）

**用户故事**：
> 作为一名玩家，我希望看到当前游戏分数和历史最高分，这样我有动力不断挑战更高记录。

**功能描述**：

1. **当前分数**
   - 页面顶部实时显示当前局游戏累计分数
   - 每次合并时分数增加，并有短暂的跳动动画

2. **最高分**
   - 使用 `localStorage` 持久化存储历史最高分
   - 当当前分数超过最高分时，实时更新最高分显示
   - 页面关闭重新打开后最高分仍然保留

**验收标准**：
- [ ] 当前分数在每次合并后实时更新
- [ ] 最高分在当前分数超越时自动更新
- [ ] 刷新页面后最高分数据不丢失
- [ ] 新游戏开始时当前分数归零，最高分保留

---

### 3.4 【F-04】游戏状态管理（P0）

**用户故事**：
> 作为一名玩家，我希望在达成 2048 时收到胜利提示、在无法继续时收到失败提示，这样我清楚地知道游戏结果。

**功能描述**：

1. **胜利判定**
   - 当棋盘上出现数值为 2048 的方块时，弹出胜利提示
   - 提示内容："恭喜！你成功合成了 2048！"
   - 提供"继续游戏"和"重新开始"两个选项

2. **失败判定**
   - 当棋盘所有格子被填满且没有任何相邻方块可合并时，判定失败
   - 弹出失败提示："游戏结束！"
   - 显示最终分数，提供"重新开始"按钮

**验收标准**：
- [ ] 合成 2048 方块时正确弹出胜利提示
- [ ] 棋盘满且无可合并方块时正确弹出失败提示
- [ ] 胜利后选择"继续游戏"可以继续操作
- [ ] 胜利/失败弹窗不遮挡最终棋盘状态（半透明遮罩）

---

### 3.5 【F-05】重新开始（P0）

**用户故事**：
> 作为一名玩家，我希望随时可以重新开始游戏，这样当局面不理想时我可以快速重来。

**功能描述**：

- 页面上方提供"新游戏"按钮
- 点击后重置棋盘状态、当前分数归零
- 重新随机生成 2 个初始方块
- 最高分不受影响

**验收标准**：
- [ ] 点击"新游戏"按钮后棋盘完全重置
- [ ] 当前分数归零
- [ ] 最高分保持不变
- [ ] 游戏进行中和游戏结束后均可点击

---

### 3.6 【F-06】方块动画（P1）

**用户故事**：
> 作为一名玩家，我希望方块移动和合并时有流畅的动画效果，这样游戏体验更加生动有趣。

**功能描述**：

1. **出现动画**：新方块从 0 缩放到正常大小（scale 0 → 1），时长 ~200ms
2. **滑动动画**：方块从原位置平滑移动到目标位置，时长 ~150ms
3. **合并动画**：合并瞬间方块短暂放大再恢复（scale 1 → 1.2 → 1），时长 ~200ms
4. **分数变化动画**：分数增加时有短暂的数字跳动/缩放效果

**验收标准**：
- [ ] 新方块出现时有缩放弹出效果
- [ ] 方块移动时有平滑过渡动画
- [ ] 方块合并时有"弹跳"放大效果
- [ ] 动画流畅无卡顿（60fps）
- [ ] 所有动画时长合理，不影响操作节奏

---

### 3.7 【F-07】响应式布局（P1）

**用户故事**：
> 作为一名玩家，我希望在手机和电脑上都有良好的游戏体验，这样我可以在任何设备上玩。

**功能描述**：

- 棋盘大小根据屏幕宽度自适应
- 移动端：棋盘宽度约为屏幕宽度的 90%，最大不超过 500px
- 桌面端：棋盘固定宽度 500px，居中显示
- 文字大小、方块间距随棋盘大小等比缩放

**验收标准**：
- [ ] 在 375px 宽度屏幕上棋盘完整显示、不溢出
- [ ] 在 1920px 宽度屏幕上棋盘居中、大小适中
- [ ] 方块内数字在各尺寸下清晰可读
- [ ] 横竖屏切换时布局自动适配

---

### 3.8 【F-08】撤销功能（P2）

**用户故事**：
> 作为一名玩家，我希望可以撤销上一步操作，这样误操作时有一次后悔的机会。

**功能描述**：

- 提供"撤销"按钮
- 仅支持撤销最近一步操作
- 撤销后恢复上一步的棋盘状态和分数
- 连续撤销无效（不能撤销多步）

**验收标准**：
- [ ] 点击撤销后棋盘和分数恢复到上一步状态
- [ ] 连续点击撤销不会继续回退
- [ ] 游戏刚开始时撤销按钮禁用
- [ ] 撤销按钮状态有视觉区分（可用/不可用）

---

### 3.9 【F-09】游戏继续（P2）

**用户故事**：
> 作为一名玩家，合成 2048 后我希望可以继续挑战更大的数字，这样增加游戏的可玩性。

**功能描述**：

- 胜利弹窗中提供"继续游戏"按钮
- 点击后关闭弹窗，游戏可继续操作
- 继续游戏后不再重复弹出胜利提示
- 理论上可以继续合成 4096、8192 等更大数字

**验收标准**：
- [ ] 胜利后点击"继续游戏"可正常继续操作
- [ ] 继续游戏后不会再次弹出胜利提示
- [ ] 继续游戏中分数正常累加
- [ ] 超过 2048 的方块（4096 等）有对应的颜色样式

## 5. 非功能需求

### 5.1 性能要求

| 指标 | 要求 |

| 平台 | 最低要求 |
|------|---------|

| Safari | ≥ 14 |
| Firefox | ≥ 88 |
| Edge | ≥ 90 |

### 5.3 技术约束

- 纯前端实现，无后端依赖
- 推荐技术栈：HTML + CSS + JavaScript（或 TypeScript）
- 可选用轻量框架（如 Vue / React），但不强制
- 数据持久化使用 `localStorage`

### 5.4 可访问性

- 方块颜色区分度满足 WCAG AA 对比度标准
- 键盘可完全操作（无需鼠标）

### A. 核心算法伪代码 — 向左滑动

```
function slideLeft(row):
    // 1. 移除空格，紧凑排列
    compact = row.filter(cell => cell != 0)
    
    // 2. 从左到右合并相邻相同方块
    for i = 0 to compact.length - 2:
        if compact[i] == compact[i+1]:
            compact[i] = compact[i] * 2
            score += compact[i]
            compact.splice(i+1, 1)
    
    // 3. 右侧补零至长度为 4
    while compact.length < 4:
        compact.push(0)
    
    return compact
```

> 其他三个方向可通过矩阵旋转/转置复用此逻辑。
