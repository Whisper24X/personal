# Test Cases: 渠道配置扩展

## Overview

- **Feature**: 渠道配置扩展（渠道配置入口、展示与新增、CSV 导入/映射联动）
- **Requirements Source**: [PRD.md](../PRD.md) — 渠道订单管理 - 渠道配置扩展
- **Test Coverage**: 功能测试、边界测试、异常测试、状态转换测试
- **Last Updated**: 2025-03-16

---

## Test Case Categories

### 1. Functional Tests

覆盖正常用户流程与核心功能。

#### TC-F-001: 渠道订单管理页存在「渠道配置」按钮并点击打开弹窗

- **Requirement**: PRD 功能 1（渠道配置入口），AC1、AC2
- **Priority**: High
- **Preconditions**:
  - 用户已登录管理后台，具备渠道订单管理权限
  - 已进入渠道订单管理页
- **Test Steps**:
  1. 在渠道订单管理页找到 extra-buttons 区域
  2. 确认存在「渠道配置」按钮
  3. 点击「渠道配置」按钮
  4. 观察是否在 2 秒内打开渠道配置弹窗/抽屉
- **Expected Results**:
  - extra-buttons 区域存在「渠道配置」按钮
  - 点击后 2 秒内打开渠道配置弹窗/抽屉
- **Postconditions**: 渠道配置弹窗/抽屉已打开

---

#### TC-F-002: 渠道配置弹窗内展示渠道列表区域

- **Requirement**: PRD 功能 1 AC3、功能 2 AC1
- **Priority**: High
- **Preconditions**:
  - 用户已登录管理后台
  - 渠道配置弹窗/抽屉已打开
- **Test Steps**:
  1. 打开渠道配置弹窗（通过点击「渠道配置」按钮）
  2. 查看弹窗/抽屉内是否展示渠道列表区域
  3. 确认列表区域可见且可识别（可为空列表或已有数据）
- **Expected Results**:
  - 弹窗/抽屉内展示渠道列表区域
  - 列表展示历史配置渠道与新增渠道（若有）
- **Postconditions**: 渠道列表区域已展示

---

#### TC-F-003: 新增渠道（名称+编码）成功，列表刷新且无删除/编辑入口

- **Requirement**: PRD 功能 2 AC2、AC3、AC4
- **Priority**: High
- **Preconditions**:
  - 渠道配置弹窗已打开
  - 已知未使用的渠道名称与编码（如「测试渠道A」「TEST_CODE_001」）
- **Test Steps**:
  1. 在渠道配置弹窗中点击「新增渠道」或「新增」
  2. 填写名称、编码（必填项）
  3. 提交表单
  4. 等待系统反馈（成功提示、列表刷新）
  5. 确认列表中出现新渠道
  6. 确认列表/行内无删除、编辑入口
- **Expected Results**:
  - 支持新增渠道，必填项为名称、编码
  - 新增成功后列表刷新，新渠道出现在列表中
  - 无删除、编辑入口
- **Postconditions**: 新渠道已持久化并展示在列表中

---

#### TC-F-004: 导入弹窗「购买渠道」下拉展示所有已配置渠道

- **Requirement**: PRD 功能 3 AC1
- **Priority**: High
- **Preconditions**:
  - 用户已登录管理后台，已进入渠道订单管理页
  - 系统中已有至少一个已配置渠道（历史或本次新增）
- **Test Steps**:
  1. 点击「导入渠道订单」按钮，打开导入弹窗
  2. 定位「购买渠道」下拉框并点击展开
  3. 核对下拉选项与渠道配置列表中的渠道是否一致
- **Expected Results**:
  - 导入弹窗「购买渠道」下拉框展示所有已配置渠道
  - 选项与渠道配置列表一致
- **Postconditions**: 导入弹窗已打开，购买渠道下拉已展示

---

#### TC-F-005: 新增渠道后，导入弹窗中可选中该渠道并成功导入 CSV

- **Requirement**: PRD 功能 3 AC2、AC3
- **Priority**: High
- **Preconditions**:
  - 已在渠道配置中新增一条渠道并关闭弹窗
  - 准备一份符合要求的 CSV 文件（表头与映射一致）
- **Test Steps**:
  1. 再次打开「导入渠道订单」弹窗（或刷新后打开）
  2. 在「购买渠道」下拉框中选择刚新增的渠道
  3. 上传准备好的 CSV 文件
  4. 点击确定/提交，等待导入完成
  5. 确认出现导入成功反馈
- **Expected Results**:
  - 新增渠道后，导入弹窗中可选中该渠道（需关闭重开或刷新）
  - 选择新渠道并上传 CSV 可成功导入
- **Postconditions**: 订单已按新渠道导入成功

---

#### TC-F-006: 映射配置弹窗 Tab 按已配置渠道展示，新渠道 Tab 可配置并保存

- **Requirement**: PRD 功能 4 AC1、AC2、AC3
- **Priority**: High
- **Preconditions**:
  - 已进入渠道订单管理页，系统中已有已配置渠道
  - 若验证新渠道 Tab，需先新增渠道并关闭渠道配置弹窗
- **Test Steps**:
  1. 点击「CSV映射配置」按钮，打开映射配置弹窗
  2. 确认 Tab 列表与已配置渠道一致
  3. 若有新渠道，确认存在该渠道对应 Tab
  4. 切换到新渠道 Tab，配置至少一条字段映射并保存
  5. 确认保存成功提示
- **Expected Results**:
  - CSV 映射配置弹窗 Tab 按已配置渠道展示
  - 新增渠道后，映射配置弹窗中出现该渠道 Tab（需关闭重开或刷新）
  - 新渠道 Tab 可正常配置字段映射并保存
- **Postconditions**: 映射配置已保存

---

#### TC-F-007: 端到端 — 渠道配置 → 新增 → 导入选新渠道 → 映射配置新渠道 Tab

- **Requirement**: PRD §7 主路径、§6.3 场景 1 与场景 3
- **Priority**: High
- **Preconditions**:
  - 用户已登录管理后台，已进入渠道订单管理页
  - 准备未使用的渠道名称、编码及符合格式的 CSV 文件
- **Test Steps**:
  1. 点击「渠道配置」，打开渠道配置弹窗
  2. 点击「新增渠道」，填写名称与编码，提交
  3. 确认列表刷新且新渠道出现，关闭渠道配置弹窗
  4. 点击「导入渠道订单」，在购买渠道下拉中选择新渠道，上传 CSV，提交导入
  5. 确认导入成功
  6. 点击「CSV映射配置」，确认存在新渠道 Tab，切换至该 Tab，配置字段映射并保存
  7. 确认保存成功
- **Expected Results**:
  - 新渠道出现在列表、导入下拉框、映射 Tab 中
  - 导入与映射可正常使用
- **Postconditions**: 新渠道全流程可用

### 2. Edge Case Tests

覆盖边界条件与非常规输入。

#### TC-E-001: 渠道列表为空时展示空状态，仍可点击新增

- **Requirement**: PRD 功能 2 边界
- **Priority**: Medium
- **Preconditions**:
  - 渠道配置弹窗可打开，且当前无任何已配置渠道（或测试环境已清空）
- **Test Steps**:
  1. 打开渠道配置弹窗
  2. 确认列表区域展示为空状态（空列表或空状态提示）
  3. 确认存在「新增渠道」或「新增」入口并可点击
  4. 点击新增，确认可进入新增表单
- **Expected Results**:
  - 渠道列表为空时展示空状态
  - 仍可点击新增并进入新增流程
- **Postconditions**: 可正常发起新增

---

#### TC-E-002: 新增时编码与已有渠道重复，提交被拒

- **Requirement**: PRD 功能 2 AC5
- **Priority**: High
- **Preconditions**:
  - 渠道配置弹窗已打开，列表中已存在某渠道（已知其编码）
- **Test Steps**:
  1. 点击「新增渠道」，填写名称（任意）与编码（与已有渠道编码相同）
  2. 提交表单
  3. 观察系统反馈
  4. 确认列表未新增该条记录
- **Expected Results**:
  - 编码重复时提示「该编码已存在，请更换」或等价错误信息
  - 不提交、不刷新列表为新记录
- **Postconditions**: 列表未变化，用户可修改编码后重试

---

#### TC-E-003: 新增时名称或编码必填未填，提交被拒并提示字段

- **Requirement**: PRD 功能 2 出错兜底（必填项未填时提示具体字段）
- **Priority**: Medium
- **Preconditions**:
  - 渠道配置弹窗已打开
- **Test Steps**:
  1. 点击「新增渠道」
  2. 不填名称或编码（或两者都不填），直接提交
  3. 观察校验提示
  4. 仅填名称不填编码，提交，观察提示
  5. 仅填编码不填名称，提交，观察提示
- **Expected Results**:
  - 必填项未填时提示具体字段（如「请填写名称」「请填写编码」）
  - 不提交，直至必填项填写完整
- **Postconditions**: 表单仍可编辑，用户可补全后重试

### 3. Error Handling Tests

覆盖错误场景与失败模式。

#### TC-ERR-001: 渠道配置列表加载失败，提示「加载失败，请重试」

- **Requirement**: PRD 功能 1 出错兜底
- **Priority**: Medium
- **Preconditions**:
  - 可通过 mock 或断网等方式使渠道配置列表接口失败
- **Test Steps**:
  1. 在渠道订单管理页点击「渠道配置」
  2. 触发渠道配置弹窗打开但列表加载失败（如接口 500 或超时）
  3. 观察弹窗内或全局提示
- **Expected Results**:
  - 出现加载失败提示，内容包含「加载失败，请重试」或等价可执行建议
  - 用户可知失败原因并可重试
- **Postconditions**: 弹窗可关闭，用户可再次点击「渠道配置」重试

---

#### TC-ERR-002: 新增渠道接口失败，提示可重试/明确错误

- **Requirement**: PRD 功能 2、§10 可恢复性
- **Priority**: Medium
- **Preconditions**:
  - 可通过 mock 使新增渠道接口返回失败（如 500、网络错误）
- **Test Steps**:
  1. 打开渠道配置弹窗，点击「新增渠道」
  2. 填写合法名称与编码，提交
  3. 模拟接口失败
  4. 观察错误提示与界面状态
- **Expected Results**:
  - 出现错误提示，信息明确（如网络错误、服务器错误）
  - 提示中包含可执行的下一步建议（如「请重试」）
  - 用户可重试提交
- **Postconditions**: 表单数据可保留或可重新填写后重试

---

#### TC-ERR-003: 导入弹窗渠道列表加载失败，提示「加载渠道失败，请重试」

- **Requirement**: PRD 功能 3 出错兜底
- **Priority**: Medium
- **Preconditions**:
  - 可通过 mock 使导入弹窗内渠道列表接口失败
- **Test Steps**:
  1. 点击「导入渠道订单」，打开导入弹窗
  2. 触发购买渠道下拉数据加载失败
  3. 观察弹窗内或全局提示
- **Expected Results**:
  - 出现提示，内容包含「加载渠道失败，请重试」或等价可执行建议
  - 用户可知失败原因并可重试（如关闭弹窗再开）
- **Postconditions**: 导入弹窗可关闭，用户可再次打开重试

---

#### TC-ERR-004: 映射配置弹窗渠道/Tab 加载失败，提示「加载渠道失败，请重试」

### 4. State Transition Tests

覆盖状态变化与联动。

#### TC-ST-001: 新增渠道成功后，不关闭弹窗则列表刷新出现新渠道

- **Requirement**: PRD 功能 2 系统状态变化（新增成功后刷新列表）
- **Priority**: High
- **Preconditions**:
  - 渠道配置弹窗已打开
- **Test Steps**:
  1. 记录当前列表条数或最后一条渠道名称/编码
  2. 点击「新增渠道」，填写名称与编码，提交
  3. 不关闭弹窗，观察列表区域
  4. 确认新渠道出现在列表中且条数+1（或最后一条为新渠道）
- **Expected Results**:
  - 新增成功后列表刷新，新渠道出现在列表中（无需关闭弹窗）
- **Postconditions**: 列表已更新，新渠道可见

---

#### TC-ST-002: 新增渠道后关闭弹窗再打开导入，购买渠道下拉含新渠道

- **Preconditions**:

- **Test Steps**:

  3. 展开「购买渠道」下拉框
  4. 确认刚新增的渠道出现在选项中
- **Expected Results**:

  - 购买渠道下拉含新渠道
- **Postconditions**: 导入弹窗已打开，新渠道可选

---

#### TC-ST-003: 新增渠道后关闭弹窗再打开映射配置，出现新渠道 Tab

## Notes

- **PRD 开放问题（§15）**：渠道唯一标识/编码规则、历史渠道与新增渠道数据来源、渠道配置持久化策略尚未定稿，测试时以当前产品/技术约定为准；若后续规则变更，需同步更新本用例（尤其是编码唯一性 TC-E-002 与数据来源一致性相关用例）。
- **「需关闭重开或刷新」**：与 PRD 功能 3 AC2、功能 4 AC2 一致，新增渠道后导入弹窗/映射配置弹窗需关闭再打开或整页刷新后，新渠道才会出现在下拉框或 Tab 中；状态类用例 TC-ST-002、TC-ST-003 按此约定设计。
- **覆盖端**：仅管理后台（ainative-shadow），无多端差异。
- **非功能**：PRD §10 要求渠道列表 2 秒内展示、新增成功率 ≥99%、出错可重试；性能与稳定性可在专项测试或自动化中补充断言。
