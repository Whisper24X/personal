## 第二部分：测试用例

### 用例编写规范

#### 优先级定义


| 优先级 | 定义   | 说明            |
| --- | ---- | ------------- |
| P0  | 核心功能 | 主流程、核心业务，必须通过 |
| P1  | 重要功能 | 重要分支、常用功能     |
| P2  | 一般功能 | 边界条件、异常处理     |
| P3  | 低优先级 | 极端场景、优化建议     |


#### 用例格式说明

- 采用 **Given-When-Then** 格式（BDD风格）
- **Given**：前置条件和测试数据准备
- **When**：执行的操作步骤（含具体导航路径，可直接映射为 Playwright action）
- **Then**：预期结果验证（仅页面可观测结果，可直接映射为 Playwright assertion）

#### TC-001：登录 - 使用正确凭据进入系统


| 属性   | 值            |
| ---- | ------------ |
| 用例ID | TC-auth-001  |
| 类型   | AINative 工作台 |
| 优先级  | P0           |
| 前置条件 | 已存在可登录的测试账号  |
| 关联需求 | AINative-通用  |


**Given**：

- 浏览器未登录或已打开 `/login`
- 已知有效用户名与密码

**When**：

- 访问 `/login` → 等待登录页加载完成
- 在用户名输入框填写测试用户名，等待输入完成
- 在密码输入框填写测试密码，等待输入完成
- 点击「登录」按钮 → 等待跳转完成

**Then**：

- 页面离开登录页（URL 不再为 `/login`）
- 出现工作区布局（含侧栏与顶栏）

#### TC-003：工作区 - 侧栏选择项目后进入仪表盘


| 属性   | 值                            |
| ---- | ---------------------------- |
| 用例ID | TC-ws-001                    |
| 类型   | AINative 工作台                 |
| 优先级  | P0                           |
| 前置条件 | 已登录；账号下至少有一条业务线且该业务线下至少有一个项目 |
| 关联需求 | AINative-通用                  |


**Given**：

- 用户已登录并进入带侧栏的工作区布局
- 侧栏「项目」分组下可见至少一个项目名称

**When**：

- 侧栏点击「工作台」→ 等待页面加载
- 在侧栏「项目」分组中点击目标项目名称 → 等待路由与内容刷新

**Then**：

- 顶栏标题区域展示「仪表盘」（或与当前路由 `meta.title` 一致）
- 主内容区展示欢迎语「Hi,」与项目名称、任务统计相关文案（非「未选择项目」空态）
