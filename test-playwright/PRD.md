## 2. MRD 摘要与需求背景

### 2.1 一句话问题定义（来自 MRD）

> 为【运营人员、管理员】解决【渠道配置依赖后端、CSV 导入与映射配置与渠道不同步、无统一渠道视图】问题，从而带来【自主管理渠道、新渠道配置后即可导入、统一配置视图】价值。

### 2.2 现状与动因

- 当前用户/业务面临的问题：
  1. 渠道来源仅依赖后端接口，运营无法在管理后台自主新增或查看已配置渠道
  2. CSV 导入、CSV 映射配置需后端同步新渠道才能使用，存在配置滞后
  3. 渠道列表分散在接口与配置中，无统一管理入口
- 不解决的后果或机会成本：
  - 新渠道接入周期长，依赖后端发版与配置变更
  - 运营在导入 CSV 时无法选择新渠道，或映射配置中缺少对应 Tab，导致导入失败或数据不一致
  - 渠道配置分散、不可追溯，增加运维与排查成本
- 数据或事实依据（至少 1 条）：
  - > 📚 来源：[业务规则] - docs/业务逻辑梳理-AI知识库.md：研学系统支持小程序、抖音、微店、视频号小店等销售渠道，业务扩展中常需接入新渠道

### 2.3 关键假设（可验证）

| 假设                         | 验证方式                     | 验证窗口   | 风险 |
| ---------------------------- | ---------------------------- | ---------- | ---- |
| 运营可自主完成新渠道接入     | 新渠道从配置到可导入耗时 < 1 天 | 上线后 2 周 | 低   |
| 渠道配置与 CSV 模块数据一致  | 配置渠道与导入/映射渠道 100% 一致 | 上线后 1 周 | 中   |
| 不删除渠道可满足业务需求     | 运营反馈无删除诉求           | 需求评审   | 低   |

### 2.4 约束与假设

- 渠道配置数据需与后端 channel 接口对接，新增渠道需持久化
- 需与现有 CSV 导入（ImportOrderDialog）、CSV 映射配置（CsvMappingDialog）组件兼容
- 本期不做渠道删除、编辑、启用/停用、渠道级权限

## ⭐ 4. 用户体验与交互设计要求（Experience Spec）

> **本章是体验"规格"，不是设计稿**

### 4.1 体验目标（Experience Goals）

- 用户完成任务时应感受到的核心变化：
  - 更快：新渠道接入无需等待后端发版
  - 更简单：一处配置，导入与映射自动联动
  - 更确定：统一渠道列表，配置可追溯
- 本需求希望减少的用户负担：
  - 操作步骤：减少与后端沟通、等待配置的步骤
  - 不确定性：消除「新渠道是否已同步」的疑虑

### 4.2 核心体验指标（UX Metrics）

| 指标             | 定义                         | 目标值       | 关联功能           |
| ---------------- | ---------------------------- | ------------ | ------------------ |
| 任务完成率       | 新增渠道后成功导入 CSV 的比例 | ≥ 95%        | 渠道配置、CSV 导入 |
| 中途退出率       | 渠道配置弹窗未完成即关闭的比例 | < 10%        | 渠道配置           |
| 关键步骤平均耗时 | 新增渠道到可导入的耗时       | < 5 分钟     | 全流程             |
| 出错后恢复成功率 | 新增失败后重试成功的比例     | ≥ 90%        | 渠道配置           |

### 4.3 强制体验原则（MUST）

- [MUST] 任一用户操作后 ≤ 2 秒内必须有系统反馈（加载、成功、失败）
- [MUST] 用户始终清楚「当前步骤」与「下一步会发生什么」（如：新增渠道 → 选择渠道导入 → 配置映射）
- [MUST] 出错时给出**可执行的下一步建议**（如：编码重复时提示「请更换编码」）
- [MUST] 不出现"无解释的自动跳转 / 自动失败"

### 4.4 UI / 交互约束（非视觉稿）

- 信息密度：中
- 是否允许一次性多决策点：否（新增渠道与导入、映射分步进行）
- 是否允许系统自动决策：是（新渠道自动出现在导入、映射中，无需用户额外操作）
- 多端要求：仅管理后台，无多端差异

## 5. 需求范围与优先级

### 5.1 In Scope（本期包含）

- P0：
  1. 渠道配置入口（extra-buttons 区域「渠道配置」按钮）
  2. 渠道配置展示与新增（列表展示、新增渠道名称与编码，不支持删除）

### 5.3 关键取舍说明

- 为什么做新增不做删除：保证历史数据与映射配置完整性，降低误操作风险
- 对用户体验的影响判断：误新增渠道无法清理，通过新增前确认提示缓解，必要时后续迭代支持「停用」

### 6.3 核心场景（可验收）

- 场景 1：**新增渠道并完成首次导入**
  - 用户目标：在渠道订单管理页新增渠道，并在 CSV 导入中选择该渠道上传文件
  - 触发：业务方接入新销售渠道
  - 关键步骤：点击「渠道配置」→ 新增渠道（名称、编码）→ 点击「导入渠道订单」→ 选择新渠道 → 上传 CSV

  - 关键步骤：点击「渠道配置」→ 查看渠道列表
  - 成功定义：列表展示历史配置渠道与新增渠道
- 场景 3：**CSV 映射配置联动**
  - 用户目标：为新渠道配置 CSV 字段映射
  - 触发：完成新渠道配置后需配置映射
  - 关键步骤：点击「CSV 映射配置」→ 选择新渠道 Tab → 配置字段映射
  - 成功定义：新渠道 Tab 自动出现，可配置映射

## 7. 端到端关键流程（Key Flow）

### 7.1 主路径

1. 运营进入渠道订单管理页
2. 点击 extra-buttons 区域「渠道配置」按钮
3. 打开渠道配置弹窗/抽屉，查看渠道列表
4. 点击「新增渠道」，填写名称、编码，提交
5. 关闭渠道配置，点击「导入渠道订单」
6. 在购买渠道下拉框中选择新渠道，上传 CSV 文件，提交导入
7. 点击「CSV 映射配置」，选择新渠道 Tab，配置字段映射并保存

### 7.2 结果定义

- 成功的定义：新渠道出现在列表、导入下拉框、映射 Tab 中，导入与映射可正常使用
- 失败的定义：新增失败、导入时无新渠道、映射中无新渠道 Tab
- 用户主动放弃的定义：未完成新增即关闭弹窗、未完成导入即关闭

### 8.2 功能规格（逐条填写，P0 必填）

#### 功能 1：渠道配置入口

**A. 用户视角**

- 用户目标：从渠道订单管理页快速进入渠道配置
- 用户输入 / 操作：点击「渠道配置」按钮
- 用户可感知反馈：打开渠道配置弹窗/抽屉

**B. 系统行为**

- 触发条件：用户点击 extra-buttons 区域的「渠道配置」按钮
- 系统状态变化：展示渠道配置弹窗/抽屉
- 返回结果类型：成功（弹窗展示）

**C. 体验与规则约束**

- 不允许出现的体验：点击无响应、长时间无反馈
- 默认行为：弹窗/抽屉展示渠道列表
- 出错兜底策略：加载失败时提示「加载失败，请重试」

**D. 验收标准（AC）**

- AC1：渠道订单管理页 extra-buttons 区域存在「渠道配置」按钮
- AC2：点击后 2 秒内打开渠道配置弹窗/抽屉
- AC3：弹窗/抽屉内展示渠道列表区域

**E. 数据与归因**

- 关联 KPI：任务完成率
- 关键埋点事件：channel_config_click

#### 功能 2：渠道配置展示与新增

**A. 用户视角**

- 用户目标：查看已配置渠道列表，并新增渠道（名称、编码）
- 用户输入 / 操作：在弹窗中查看列表；点击「新增」填写名称、编码并提交
- 用户可感知反馈：列表展示；新增成功后列表刷新、成功提示

**B. 系统行为**

- 触发条件：弹窗打开时加载列表；用户提交新增表单
- 系统状态变化：列表展示历史配置渠道与新增渠道；新增成功后持久化并刷新列表
- 返回结果类型：成功 / 失败（如编码重复）

**C. 体验与规则约束**

- 不允许出现的体验：无删除按钮（本期不支持删除）
- 默认行为：列表按创建时间或名称排序；编码唯一性校验
- 出错兜底策略：编码重复时提示「该编码已存在，请更换」；必填项未填时提示具体字段

**D. 验收标准（AC）**

- AC1：渠道配置弹窗展示渠道列表（历史配置 + 新增）
- AC2：支持新增渠道，必填项：名称、编码
- AC3：新增成功后列表刷新，新渠道出现在列表中
- AC4：无删除、编辑入口
- AC5：编码重复时提示错误且不提交

**E. 数据与归因**

- 关联 KPI：渠道配置操作成功率
- 关键埋点事件：channel_config_list_view、channel_add_success、channel_add_fail

#### 功能 3：CSV 导入与渠道联动

**A. 用户视角**

- 用户目标：在导入渠道订单时，购买渠道下拉框包含所有已配置渠道（含新增）
- 用户输入 / 操作：打开导入弹窗，选择购买渠道
- 用户可感知反馈：下拉框展示完整渠道列表，可选择新渠道

**B. 系统行为**

- 触发条件：打开导入弹窗时加载渠道列表；渠道配置新增后，下次打开导入弹窗时包含新渠道
- 系统状态变化：购买渠道下拉框数据源与渠道配置列表一致
- 返回结果类型：成功（下拉框展示一致）

**C. 体验与规则约束**

- 不允许出现的体验：新渠道在配置中存在但导入中不可选
- 默认行为：渠道列表与渠道配置接口/数据源一致，实时或打开时刷新
- 出错兜底策略：渠道列表加载失败时提示「加载渠道失败，请重试」

**D. 验收标准（AC）**

- AC1：导入弹窗「购买渠道」下拉框展示所有已配置渠道
- AC2：新增渠道后，导入弹窗中可选中该渠道（需关闭重开或刷新）
- AC3：选择新渠道并上传 CSV 可成功导入

**E. 数据与归因**

- 关联 KPI：渠道一致性、新渠道接入效率
- 关键埋点事件：channel_import_channel_select

**C. 体验与规则约束**

## 12. 风险与应对

| 风险                         | 发生概率 | 影响 | 应对策略                                       |
| ---------------------------- | -------- | ---- | ---------------------------------------------- |
| 渠道配置与导入/映射数据不一致 | 中       | 中   | 设计时明确渠道数据源唯一、刷新时机统一         |
| 后端接口未就绪               | 中       | 中   | 前后端并行设计，明确接口契约                   |
| 误新增渠道无法清理           | 低       | 低   | 新增前确认提示，后续迭代可支持「停用」         |

## 13. 发布、灰度与回滚

- 发布方式：全量
- 灰度节奏：无
- 观察指标：渠道配置操作成功率、渠道一致性
- 停止 / 回滚阈值：配置成功率 < 95% 或一致性 < 100%
- 用户侧可感知变化说明：渠道订单管理页新增「渠道配置」按钮，导入与映射的渠道来源与配置一致
