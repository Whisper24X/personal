### 输出（仅更新 `docs/{{gitBranch}}/TEST.md`）

按 `testcase-author` 的编写步骤与检查清单，将用例改写/补全为 **V2-Lite（A–J）** 结构；**所有步骤、断言与证据均须可在浏览器内完成或观测**（DOM/页面文案/路由/浏览器网络请求与响应摘要/页内列表或详情回读）。在 `TEST.md` 中需体现：

1. **任务目标**（1 句话）与 **完成断言**（最多 2–3 条）。
2. **样本策略**：优先样本、备用样本、**样本偏离口径**（强约束）。
3. **Stage0 预检**：数据/权限/入口/能力位。
4. **解阻预算**：最大循环数 N（默认 2，L2 建议 3）；round1/2/3 的**单变量**梯度。
5. **最小证据集**与（若有写操作）**回滚要求**。
6. **失败归因**是否可落到 `PASS` / `FAIL` / `BLOCKED_*`。

若文档中仍使用 **Given / When / Then** 表述，请按下表**映射到 V2-Lite**，并在同一用例下补全对应小节（避免两套结论混写）：

| 截图语义 | 对应 V2-Lite 要点 |
| --- | --- |
| **Given**（可执行前置） | B 前置状态 + D Stage0 预检 + C 样本与入口 |
| **When**（导航与等待） | C 主入口/菜单路径；E 解阻轮次中的交互/等待/定位策略 |
| **Then**（可观测断言） | B 完成断言 + G 成功/失败最小证据 + H 结论归因 |

**自动化相关补充（Web/Playwright，与侧栏导航一致）：** 在 **When** 对应段落中，补充侧栏导航路径、关键等待点（页面稳定、网络请求完成、关键元素可见等）；在 **Then** 对应段落中，补充**仅基于页面与浏览器上下文**的可观测断言；必要时增加 **Playwright 友好的元素选择器建议**与**自动化可行性说明**（仍须服从 V2-Lite 的证据与归因约束）。
