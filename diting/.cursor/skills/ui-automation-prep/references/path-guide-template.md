# 自动化就绪用例 — Given/When/Then 书写规范

## 目录

- 一、Given 前置条件格式
- 二、When 导航步骤格式（含 Tab 切换、元素描述、元素选择）
- 三、Then 断言格式
- 四、完整示例（TC-CHANNEL-001、TC-CSV-001）
- 五、关键原则

## 一、Given 前置条件格式

Given 仅描述当前 Playwright 浏览器自动化环境可以**执行或验证**的前提条件，并且不能删除本 case 的核心业务前提。

1. **登录状态**：可通过账号密码或预认证完成
2. **页面可观测的初始状态**：可通过 snapshot/DOM/页面文本验证
3. **当前可控测试能力**：已存在样本、seed、mock、故障注入能力

```markdown
**Given**：

- 已通过指定账号或预认证登录管理后台
- 目标页面可正常访问
```

### Given 禁止写法

| 禁止类型 | 错误示例 | 正确写法 |
| --- | --- | --- |
| 硬编码数据量 | "设备列表中有至少 3 台设备" | 若数量非核心断言，改为"设备列表已加载且有可见设备行"；若是核心断言但当前无样本，标注 `本轮是否执行=否` |
| 指定数据状态 | "多台设备当前为任务学模式" | 有现有样本/seed 则绑定样本；没有则标注 `本轮是否执行=否` |
| 数据库条件 | "数据库中该设备 defaultMode 为 null" | 转为 UI 可观测样本前提；无法转化则不纳入本轮 |
| 不可观测条件 | "该设备为学生用设备" | 用页面可见身份/标签/样本名表达；无法观测则不纳入本轮 |
| 权限细节 | "有目标门店的设备查看权限" | "已登录具备该权限的指定账号"；无账号则不纳入本轮 |

## 二、When 导航步骤格式

在 TEST.md 测试用例的 **When** 中，导航步骤按以下格式书写：

```markdown
**When**：

- 侧栏点击「一级菜单」→ 点击子菜单「二级菜单」→ 等待[内容]加载
- 在[列表/页面]中点击目标行的「按钮名」→ 等待[下一页内容]加载
- [具体业务操作步骤...]
```

### When 规范说明

| 要素         | 格式                              | 示例                                           |
| ------------ | --------------------------------- | ---------------------------------------------- |
| 侧栏菜单     | 侧栏点击「菜单名」               | 侧栏点击「任务学管理」                         |
| 子菜单       | → 点击子菜单「菜单名」           | → 点击子菜单「门店选择」                       |
| 等待加载     | → 等待[内容描述]加载             | → 等待门店列表表格加载                         |
| 表格行内按钮 | 点击目标行的「按钮名」按钮       | 点击目标门店行的「学习模式管理」按钮           |
| 下拉框操作   | 点击「下拉框名」→ 选择「选项名」 | 点击「默认模式」下拉框 → 选择「自主学习模式」 |
| 对话框确认   | 在确认对话框中点击「确定」       | 在确认对话框中点击「确定」                     |
| Tab 切换     | 点击「Tab 名」Tab → 等待内容加载 | 点击「其他」Tab → 等待映射表单加载             |

### Tab 切换后断言

点击 Tab 后，需等待 Tab 切换完成再断言 Tab 内内容。执行 Playwright 浏览器自动化时，对 Tab 内表单/表格的定位须限定在**激活的 tab-pane** 内，避免匹配到其他 Tab 的隐藏内容。

**唯一定位约束**：定位目标应尽量 resolve 到 1 个元素；如果页面存在重复元素，需通过区域/弹窗/激活 Tab 限定范围。

**禁止写法**：`dialog.locator('.el-tabs__content, .el-tab-pane').filter(...).or(dialog.locator('.el-form'))` 会匹配多个元素。

**正确写法**：`dialog.locator('.el-tab-pane[aria-hidden="false"] .el-form').first()`。Element Plus 的 pane 不挂载 `is-active`，仅用 `aria-hidden` 控制可见性。

### 元素描述规范（辅助 Playwright 定位）

表单元素须明确「区域 + label + 控件类型」：

| 要素         | 格式                                      | 示例                                               |
| ------------ | ----------------------------------------- | -------------------------------------------------- |
| 表单下拉框   | 在[区域]中点击 label 为「X」的下拉框       | 在搜索区域点击 label 为「购买渠道」的下拉框        |
| 下拉选项选择 | 在 label 为「X」的下拉框中选择「选项名」   | 在 label 为「购买渠道」的下拉框中选择「其他」      |
| 下拉选项断言 | label 为「X」的下拉框展开后，选项列表中「Y」可见 | 购买渠道下拉展开后，选项列表中「其他」可见         |

**下拉选项定位（Tab/弹窗内）**：多 Tab 弹窗中每个 Tab 有多个 el-select，dropdown 会匹配 60+ 个元素。**禁止** `page.locator('.el-select-dropdown, .el-popper').last()`（会命中隐藏 dropdown 导致超时）。**正确**：`page.getByRole('listbox').getByRole('option', { name: '选项名' })`。

### 元素选择（供 Playwright 执行参考）

涉及表单控件、下拉选项、Tab、按钮的用例，在 **Then** 之后增加 **元素选择** 块，显式标注定位参数。类型与参数速查见 [element-plus-locators.md](element-plus-locators.md)。

| 列 | 说明 |
| --- | --- |
| 元素 | 元素描述（与 When/Then 对应） |
| 类型 | 表单项+下拉框、下拉选项、侧栏菜单、Tab、按钮、成功提示、对话框 |
| 参数 | label=X、文本=X、标题=X |
| 定位 | 对应 Playwright 可用定位策略缩写 |

## 三、Then 断言格式（与 When 联动）

When 到达的最终页面决定了 Then 可以断言的范围。每条 Then 必须是用户在 When 最终页面上肉眼可见的 UI 变化。

### When 操作类型 → Then 断言模式

| When 操作类型 | Then 断言模式 | Playwright 断言映射 |
| --- | --- | --- |
| 下拉框选择（自动保存） | 出现保存成功提示 + 字段显示值更新 | Element Plus: `.el-message--success` visible + cell `textContent` |
| 按钮点击（提交表单） | 出现操作成功提示 + 列表刷新 | Element Plus: `.el-message--success` visible + table row text |
| 筛选 + 搜索 | 列表仅展示符合条件的记录 | table rows `textContent` 验证 |
| 批量操作 + 确认 | 出现批量成功提示 + 选中项状态更新 | Element Plus: `.el-message--success` visible + rows text |
| 页面跳转 | 目标页面关键内容已加载并可见 | target element `waitFor({ state: 'visible' })` |

### Then 禁止写法

| 禁止类型 | 错误示例 | 正确写法 |
| --- | --- | --- |
| 数据库断言 | `数据库中 defaultMode 已更新` | `设备列表中该设备的默认模式列显示为「自主学习」` |
| 接口断言 | `接口返回 xxx 字段` | `页面展示 xxx 内容` |
| 硬编码时间 | `2秒内出现提示` | `出现保存成功提示` |
| 硬编码数量 | `已成功设置 3 台设备` | `出现成功数量反馈` |
| 主观描述 | `便于快速找到老师设备` | `筛选结果仅展示符合条件的设备` |
| 跨页面断言 | 断言跳转前页面的状态 | 只断言 When 最终到达的页面 |
| 模糊形容 | `「其他」与抖音、微店等渠道选项展示形式一致` | `选项列表中「其他」可见`（或删除，若前条已断言存在） |
| 模糊形容 | `「三方渠道」与现有系统字段展示形式一致` | `系统字段下拉选项列表中「三方渠道」可见`（或删除冗余条） |

### Then 具体化原则（避免模糊形容）

- **选项存在断言**：写「[区域]中 [label/列] 的选项列表中「X」可见」，不写「X 与 Y、Z 展示形式一致」
- **表格行断言**：写「[表]中存在 [列A]=「值A」、[列B]=「值B」的配置行」，不写「配置正确」
- **下拉/选项值来自源码**：When/Then 中的选项名（如「三方渠道」「其他」）须与源码 `el-option` label 或接口数据一致

## 四、完整示例

**优化前**（不可执行 Given + 抽象 When + 不可自动化 Then）：

```markdown
**Given**：

- 门店管理员已登录管理后台
- 学习模式管理页面已加载，设备列表中有至少 3 台设备
- 多台设备当前为任务学模式，需批量设为自主学习

**When**：

- 用户进入「任务学」→「学习模式管理」
- 选择目标门店，加载设备列表

**Then**：

- 数据库中 defaultMode 已更新为 free_learning
- 2秒内出现保存提示
```

**优化后**（当前环境可执行 Given + 具体 When + Playwright-ready Then）：

```markdown
**Given**：

- 已通过指定账号或预认证登录管理后台
- 学习模式管理页面可正常访问

**When**：

- 侧栏点击「任务学管理」→ 点击子菜单「门店选择」→ 等待门店列表表格加载
- 在门店列表中点击目标门店行的「学习模式管理」按钮 → 等待设备列表表格加载
- 在设备列表中找到目标设备，点击该行「默认模式」列的下拉框 → 选择「自主学习模式」→ 等待系统自动保存完成

**Then**：

- 出现保存成功提示
- 设备列表中该设备的默认模式列显示为「自主学习」
```

### TC-CHANNEL-001 风格示例（表单下拉框）

以购买渠道筛选为例，展示优化后的 When/Then 写法：

```markdown
**Given**：

- 已通过账号密码登录管理后台
- 渠道订单管理页可正常访问

**When**：

- 侧栏点击「订单管理」→ 等待子菜单展开 → 点击子菜单「渠道订单管理」→ 等待订单列表表格加载
- 在搜索区域点击 label 为「购买渠道」的下拉框 → 等待下拉选项列表展开

**Then**：

- 搜索区域中 label 为「购买渠道」的下拉框展开后，选项列表中「其他」可见

**元素选择**：

| 元素 | 类型 | 参数 | 定位 |
| --- | --- | --- | --- |
| 订单管理 | 侧栏一级菜单 | 文本=订单管理 | getByRole/locator |
| 渠道订单管理 | 侧栏子菜单 | 文本=渠道订单管理 | getByRole/locator |
| 购买渠道下拉框 | 表单项+下拉框 | label=购买渠道 | .el-form-item + .el-select |
| 下拉选项「其他」 | 下拉选项 | 文本=其他 | getByRole('listbox').getByRole('option', { name: '其他' }) |
```

### TC-CSV-001 风格示例（Tab 内表单）

以 CSV 映射配置弹窗「其他」Tab 为例，展示 Tab 切换后断言 Tab 内映射表单的正确写法：

```markdown
**When**：

- 在渠道订单管理页点击「CSV映射配置」按钮 → 等待弹窗打开 → 点击「其他」Tab → 等待映射表单加载

**Then**：

- 映射配置弹窗中存在「其他」Tab
- 当前展示「其他」渠道的映射表单区域，包含系统字段与CSV文件字段映射、订单状态值映射、服务状态值映射配置项

**元素选择**：

| 元素 | 类型 | 参数 | 定位 |
| --- | --- | --- | --- |
| CSV映射配置按钮 | 按钮 | 文本=CSV映射配置 | getByRole('button') |
| 其他 Tab | Tab | 文本=其他 | .el-tabs__item filter hasText |
| 映射配置弹窗 | 对话框 | 标题=CSV文件映射配置 | getByRole('dialog') |
| Tab 内映射表单 | Tab 内表单/表格 | 在 Tab 其他 内 | .el-tab-pane[aria-hidden="false"] .el-form |
| Tab 内下拉选项（如系统字段「三方渠道」） | 下拉选项 | 文本=选项文本 | getByRole('listbox').getByRole('option', { name: '选项文本' }) |
```

## 五、关键原则

1. **Given 仅保留当前环境可执行前提**：Given 只写 Playwright 可执行的操作（登录/预认证/mock）或可验证的 UI 状态；核心样本缺失时标注不纳入本轮，不要弱化断言硬测
2. **菜单文案来自源码**：使用路由 `meta.title` 的值，不用 PRD 描述
3. **每步标注等待**：点击后说明等待什么内容出现（表格、子菜单、下拉选项等）
4. **隐藏路由写全路径**：不在侧栏的页面，写明从哪个页面的哪个按钮进入
5. **导航和业务分离**：先写完导航步骤（到达目标页面），再写业务操作步骤
6. **Then 与 When 联动**：Then 只断言 When 最后一步所在页面上的可见变化
